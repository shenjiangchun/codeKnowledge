## 3. 构建任务

### 3.1 入口 `KnowledgeGraphTaskServiceImpl.startTask(...)`

参数：`projectPath`、`excludePaths`、`generateVector`、`generateArchitecture`、`buildMode`（默认 `REUSE`）。校验通过后调 `KgGenerationQueue.enqueue(...)`。

| 校验 | 失败表现 |
|------|---------|
| 项目路径不存在 | `IllegalArgumentException` |
| 工作区有未提交改动 | `IllegalStateException`，提示先提交再生成 |
| 取不到最新任务 | 同上 |

`getLatestTask` / `getTaskStatus` 读取时做卡死检测：`RUNNING` 超过 24 小时的任务自动标 `FAILED`。

### 3.2 队列 `KgGenerationQueue`

源码注释：保证多项目严格顺序执行，每个项目完整走完「图谱生成 → 描述生成 → 向量生成」后才开始下一个。

| 项目 | 值 |
|------|-----|
| 实现 | 单消费线程 + `LinkedBlockingQueue`（内存态） |
| 任务类型 | `KG`、`VECTOR` |
| 任务状态 | `PENDING` → `RUNNING` → `COMPLETED` / `FAILED` |
| 向量任务等待 | 每 3 秒轮询，最长 3600 秒 |
| 启动恢复 | `@PostConstruct init()`：把遗留的 `KG` 类 `RUNNING` / `PENDING` 任务标 `FAILED`；`VECTOR` 孤儿任务不恢复 |
| 对外方法 | `enqueue(...)`（3 个重载）、`enqueueIncremental`、`enqueueBatch`（3 个重载）、`getQueueStatus`、`getQueueSize` |

### 3.3 构建模式 `BuildMode`

| 模式 | 含义 |
|------|------|
| `INCREMENTAL` | 依赖 git diff 只重建变更文件，未变更节点的向量保留 |
| `REUSE` | 全量扫描 + `codeHash` 判定：命中则复用向量，未命中重算；构建末尾清理孤儿节点。仅 Java 链路支持，非 Java 项目自动降级为 `WIPE` |
| `WIPE` | 全量全删全插，确定性兜底 |

## 4. 解析链路

| 语言 | 实现 | 说明 |
|------|------|------|
| Java | `KnowledgeGraphBuilder`（约 2600 行），JavaParser + Symbol Solver | 多趟 AST 扫描：方法、类、调用关系、入口点、接口实现、数据模型；复用 `service.CodeAnalysisCoreService` 的核心方法 |
| Python | `python/PythonKnowledgeGraphBuilder`、`PythonAstVisitor` | ANTLR4 运行时 + 文法 `src/main/antlr4/.../Python3Lexer.g4`、`Python3Parser.g4`（Maven 插件生成，开 visitor、关 listener）；框架路由扫描器覆盖 Flask、FastAPI、Django、Celery |
| TS / JS / Vue | `codegraph/CodegraphSidecarService` | 子进程运行 `codegraph init -v <projectPath>`，产出 `<projectPath>/.codegraph/codegraph.db`，由 `CodegraphSqliteReader` 读取、`CodegraphToNeo4jTransformer` 写入 Neo4j |

`ProjectLanguageDetector` 判断项目语言组合；`IncrementalKnowledgeGraphBuilder` 以组合方式复用 `KnowledgeGraphBuilder`，与全量构建共享同一个 `generationSemaphore` 互斥。源码注释：增量与全量只在三处不同——只 `DETACH DELETE` 变更文件的节点、第一趟只扫变更文件、调用关系全量扫描后过滤。

存储经 `service/storage/KnowledgeGraphStorageService` 接口，实现为 `Neo4jStorageService`。

### 4.1 链接 `link/`

| 类 | 职责 |
|----|------|
| `CrossServiceLinker` | 跨服务链接编排 |
| `HttpRestLinkStrategy`、`MqLinkStrategy` | HTTP 与 MQ 两种链接策略 |
| `UrlNormalizer` | URL 归一化 |

## 6. 架构现状聚合 `AggregationPipeline`

`run(projectPath, mode, rebuiltNodeIds, changedFiles)`，`mode` 为 `FULL` 或 `INCREMENTAL`。类注释写「6 个 Stage」，实际代码是 7 个：

| Stage | 内容 | 失败处理 |
|-------|------|---------|
| 1 `ModuleStats` | `ModuleStatsAggregator.aggregate`：模块统计 + DSM | 写检查点失败并**直接返回**（后续 Stage 依赖模块数据） |
| 2 `BuildModule` | `BuildModuleDependencyAggregator`：构建模块级依赖 | 记日志，不阻断 |
| 3 `Hotspot` | `HotspotScorer`：热点风险评分 | 不阻断 |
| 4 `Churn` | `ChurnCollector`：文件变更频率 | 不阻断 |
| 5 `Community` | `CommunityDetector`：社区检测 | 写检查点失败并返回 |
| 6 `DomainName` | `DomainNameGenerator`：LLM 领域命名；增量模式下仅在漂移时执行 | 不阻断 |
| 7 `FreeLayerRole` | `FreeLayerRoleResolver`：LLM 补全游离节点层级（类级 + 包级） | 不阻断 |

`RiskScoreCalculator`：`riskScore = 复杂度归一 × 0.35 + 变更频率归一 × 0.35 + 入度归一 × 0.20 + 环惩罚 × 0.10`。复杂度用分段映射，变更频率与入度用百分位排名。

`ArchitectureAnalysisService` 是另一条独立串行队列（任务类型 `ARCH_ANALYSIS`）：后台执行「领域归纳 → 领域交互边 → 游离节点层级补全」，接口立即返回 `taskId`。源码注释说明不与 `KgGenerationQueue` 混用，避免与 KG 任务抢队列。

聚合阶段的 LLM 调用走 `aggregation/llm/DeepseekJsonClient`（直连模型网关，强制 `json_object`）。

## 10. 错误处理

| 场景 | 处理 |
|------|------|
| 路径不存在 | `IllegalArgumentException` → HTTP 400 |
| 工作区不干净 | `IllegalStateException` → HTTP 400 |
| 任务卡死（`RUNNING` 超 24 小时） | 读取时标 `FAILED` |
| 后端重启 | 遗留 `KG` 任务标 `FAILED`，需重新触发 |
| 并发构建 | 全量与增量共用 `generationSemaphore` |
| 向量任务长时间未完成 | 队列最多等 3600 秒 |
| 聚合 Stage 1 或 5 失败 | 记检查点并终止后续 Stage，不影响图谱本身 |
| 其他聚合 Stage 失败 | 记日志，不阻断 |
| codegraph 超时 | `destroyForcibly()` 并抛 `IOException` |
| LLM 建议生成失败 | 返回错误信息 |

## 11. 已知问题与扩展点

| 问题 | 说明 |
|------|------|
| 队列为内存态 | 重启丢排队项 |
| Controller 巨类 | `KnowledgeGraphController` 约 3700 行，任务、查询、架构看板混在一起 |
| V2 大面积转发 V1 | 56 个端点中多数只是把 `projectPaths` 转成 `projectPath` 调 V1 |

| V1 增量服务已废弃 | `IncrementalUpdateService` 标 `@deprecated`，检查点存在 SQLite 的 `errorMessage` 字段里，不可靠 |
| codegraph 把数据库写进目标项目 | `<projectPath>/.codegraph/codegraph.db` 可能弄脏被分析仓库 |
| 路径管理端点的标签写错 | `KgPathAdminController` 的 Cypher 用的是 `MethodNode` / `EntryPointNode` / `SqlNode`，而图里的标签是 `Method` / `EntryPoint` / `Sql`（见 [Neo4j图存储与检索](./Neo4j图存储与检索.md)）；实际命中情况未运行验证 |

| 扩展点 | 方式 |
|-------|------|
| 新增语言 | 新增 builder，并在 `KnowledgeGraphBuilder` 的多语言分发处接入 |
| 新增聚合 Stage | 实现 Stage 类并在 `AggregationPipeline.run` 中按序调用 |
| 新增查询端点 | 在 V1 增加方法，V2 做转发 |
