# 项目现状报告

输入是项目的图谱统计（域数、方法数、环、热点、上帝类、健康分）与质量数据。

## 写法

- 先给一句话结论：项目整体健康度与最值得关注的风险。
- 再按「现状 → 风险 → 建议」展开；建议要分优先级（p0 立即 / p1 近期 / p2 远期）。
- 数据有缺失就明说缺失，不要补造数字。
- 面向管理者的可读性：少堆指标，多讲影响（这些风险会带来什么开发成本）。

输出为结构化 JSON（overview schema）或 Markdown 正文，按调用方要求。
