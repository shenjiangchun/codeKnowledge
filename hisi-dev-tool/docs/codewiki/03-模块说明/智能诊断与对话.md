## 1. 模块概述

### 1.1 职责定义

**核心职责**：提供「自然语言提问 → agent 查图谱 / 日志 / APM → 流式回答」的通用对话入口；并保留一套多 Agent 协作诊断的编排框架。

本页两部分现状差别很大，先说结论：

| 部分 | 现状 |
|------|------|
| 通用对话 `/api/chat/*` | **在用**。经 [pi-agent底座](./pi-agent底座.md) 的 `ReActSession` 执行声明为 `chat` 的 agent |
| 多 Agent 协作诊断 `/api/diagnosis/*` | **框架在、实现为空**：`DiagnosticAgent` 接口在主代码中没有任何实现类，`AgentOrchestrator` 注入的 agent 列表为空 |

旧 wiki 描述的 `service/intent/` 包（`DialogController`、`IntentRecognizer`、`DialogContext`、`InterventionHandler`、`NaturalLanguageDiagnosisCoordinator` 等）在代码中不存在。

### 1.2 核心文件清单

| 文件 | 类型 | 职责 |
|------|------|------|
| `controller/AgentChatController.java` | REST（SSE） | 统一的 agent 对话入口 |
| `agent/DiagnosticAgent.java` | 接口 | 诊断 agent 契约：置信度评估与执行 |
| `agent/orchestrator/AgentOrchestrator.java` | 编排 | 按置信度筛选 agent、生成执行计划、并发执行、结果聚合；常量 `CONFIDENCE_THRESHOLD = 0.3`、`HIGH_CONFIDENCE_THRESHOLD = 0.7` |

| `agent/controller/DiagnosisController.java` | REST | 诊断接口：同步、异步、流式、响应式 |

| `agent/model/*`（7 个） | 模型 | `AgentContext`、`AgentEvent`、`AgentResult`、`DiagnosisRequest`、`DiagnosisResponse` 等 |

## 2. 通用对话 `/api/chat`

```mermaid
sequenceDiagram
    participant C as 客户端
    participant AC as AgentChatController
    participant TR as AgentTypeRegistry
    participant RS as ReActSession
    participant PI as pi 会话（chat-read 清单）

    C->>AC: POST /api/chat/{agentType} {message, sessionId, context}
    AC->>TR: get(agentType)
    alt agentType 未配置
        AC-->>C: HTTP 404
    else message 为空
        AC-->>C: HTTP 400
    end
    AC-->>C: SSE 事件 session（sessionId）
    AC->>RS: run(AgentRegistry.agent("chat"), ...)
    RS->>PI: 只读清单 chat-read
    loop message_update / text_delta
        PI-->>AC: 增量文本
        AC-->>C: SSE data {"choices":[{"delta":{"content":"..."}}]}
    end
    alt 正常结束
        AC-->>C: SSE data [DONE]
    else 无正文且有 note
        AC-->>C: SSE 事件 error（note）
    end
```

| 项目 | 值 |
|------|-----|
| 路径 | `POST /api/chat/{agentType}`，`produces = text/event-stream` |
| 请求体 | `ChatRequest(message, sessionId, context)` |
| `agentType` 合法性 | 取自 `hisi.agents.*`（`AgentTypeRegistry`）；6 个内置类型见 [应用启动与全局配置](./应用启动与全局配置.md) |
| 系统提示词 | `hisi.agents.<agentType>.system-prompt` |
| 执行 | 不论 `agentType` 是哪个，都取同一个声明 `AgentRegistry.agent("chat")`：清单 `chat-read`、无 skill、无契约 |
| 工作目录 | 后端进程的工作目录 |
| 取消判定 | 恒为 false（不取消） |
| SSE 超时 | 300 秒 |
| 鉴权 | POST，需要管理员 |

SSE 事件三种：命名事件 `session`（携带 `sessionId`）；未命名的 `data`，内容为 OpenAI 风格的 `{"choices":[{"delta":{"content":"<增量>"}}]}`；结束标记 `data: [DONE]`。出错时发命名事件 `error`。

`POST /api/chat/_list` 返回 `{agentTypes: [...]}`，供前端发现可用类型。

| 组件 | 说明 |
|------|------|
| `DiagnosticAgent` | 接口；源码注释的设计原则：单一职责、置信度机制、并发安全 |
| `AgentOrchestrator` | 构造时注入 `List<DiagnosticAgent>`，按 `getPriority()` 排序；`calculateConfidences` → `filterExecutableAgents` → `generateExecutionPlan` → 分批执行 |
| `AgentEvent` | 事件工厂方法：`requestReceived`、`agentStarted`、`agentCompleted`、`agentFailed`、`orchestrationStart`、`orchestrationEnd` 等 |
| `AgentResult` | 统一结果格式；支持携带流（`Flux<String>`） |
| `DiagnosisResult` | 聚合报告；`hasValidConclusion`、`isAllFailed` 等 |

### 3.2 现状

主代码里 `implements DiagnosticAgent` 的类为 0 个。因此 `AgentOrchestrator` 没有可执行的 agent，`/api/diagnosis/*` 目前只是一组注册在路由上的端点。

## 6. 错误处理

| 场景 | 处理 |
|------|------|
| `agentType` 未配置 | HTTP 404 |
| `message` 为空 | HTTP 400 |
| pi 未就绪 / 会话失败 | `ReActSession` 抛异常 → SSE 事件 `error` |
| 会话结束但无正文 | SSE 事件 `error`（携带 note） |
| SSE 发送失败 | 结束 emitter |
| 诊断执行线程池关闭 | 控制器与编排器的 `@PreDestroy` |

## 7. 已知问题与扩展点

| 问题 | 说明 |
|------|------|
| 诊断框架无实现 | 没有 `DiagnosticAgent` 实现类 |
| `agentType` 只影响系统提示词 | 执行的都是同一个 `chat` 声明，`provider` 字段只进日志 |
| 对话不可取消 | 取消判定恒为 false |
| 请求不落库 | 对话会话 ID 是随机串，不写 `agent_session` |

| 扩展点 | 方式 |
|-------|------|
| 新增 agent 类型 | 在 `hisi.agents.*` 增加一段 |
| 启用多 Agent 诊断 | 实现 `DiagnosticAgent` 并注册为 bean，`AgentOrchestrator` 自动收集 |
