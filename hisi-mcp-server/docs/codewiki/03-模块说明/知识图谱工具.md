## 4. 内部实现

### 4.1 路径字段互为回填：`resolveProjectParams()`

| 入参情况 | `projectPath` | `projectPaths` |
|---------|--------------|----------------|
| 只给 `projectPath` | 原值 | `[projectPath]` |
| 只给 `projectPaths` | `projectPaths[0]` | 原值 |
| 两个都给 | 原值 | 原值（`projectPaths` 优先） |
| 都不给 | `undefined` | `undefined` |

### 4.2 查询参数构造：`buildQueryParams()`

- 以 `base` 起始，追加 `projectPaths`（数组用逗号连接成一个字符串）和 `language`（有值才加）。
- `projectPath` **不会**发给后端，只用于回填 `projectPaths`。

### 4.3 各工具的参数处理差异

| 工具 | 处理 |
|------|------|
| `kg_entry_points` | `entryType` 未传或等于 `ALL` 时不发该参数 |
| `kg_downstream`、`kg_callees_tree` | `maxDepth !== undefined` 时才发 |
| `kg_mybatis_sql` | `mapperInterface`、`statementType` 有值才发 |
| `kg_dsm` | `level` 有值才发 |
| `kg_hotspots`、`kg_blast_radius` | `limit` / `maxDepth` 为真值才发（传 `0` 不会发出） |
| `kg_feign_chain`、`kg_mq_chain`、`kg_blast_radius` | 路径里的 `serviceName` / `topic` / `nodeId` 经过 `encodeURIComponent` |
| `kg_bridges` | 路径里的 `nodeId` 直接拼接，**没有**做 URL 编码 |
| `kg_api_consumers`、`kg_backend_deps` | 只发 `entryId` / `apiClientId`，转成字符串 |

### 4.4 处理函数

```ts
export async function handleKnowledgeGraphToolCall(
  toolName: string,
  args: Record<string, unknown>
): Promise<unknown>
```

`resolveProjectParams()` 的结果展开到入参之上得到 `mergedArgs`，再按工具名调用实例方法。实例由模块级变量 `_kgTools` 惰性创建，进程内只创建一次。

## 8. 错误处理

| 错误场景 | 处理 | 调用方感知 |
|---------|------|-----------|
| 后端返回非 2xx（例如缺 `projectPaths` 时的 400） | `ApiClient` 抛 `HTTP <code>: <body>` | `isError: true` + `{ success: false, error, tool }` |
| 后端超过 30 秒未响应 | `ApiClient` 抛 `Request timeout after 30000ms` | 同上 |
| 严格工具未设范围且入参不带路径 | 在入口被拦截 | `SCOPE_NOT_SET` |
| 宽松工具未设范围且入参不带路径 | 入口放行，但请求里没有 `projectPaths`；后端把它声明为必填查询参数，缺失时返回 400 | `HTTP 400: ...` |
| 后端业务失败（HTTP 200，`code` 非 200） | 本模块不判断，原样透传 | 调用方需检查响应体里的 `code` |

## 10. 已知问题与扩展点

| 已知问题 | 影响 |
|---------|------|
| `language` 入参在 20 个带项目路径的工具里都有，但后端 v2 控制器里只有 `/dashboard`、`/dsm`、`/hotspots`、`/domains`、`/service-topology` 这 5 个接口声明了 `language` 参数 | 其余 15 个工具传 `language` 不起过滤作用 |
| 6 个聚合工具（`kg_dashboard`、`kg_dsm`、`kg_hotspots`、`kg_domains`、`kg_service_topology`、`kg_blast_radius`）的 `properties` 把 `language` 写在公共片段展开之后，覆盖了带枚举的定义 | 这 6 个工具的 `language` 没有 `enum` 限制 |
| `kg_entry_points` 没有暴露分页参数；后端该接口有 `page`（默认 1）和 `pageSize`（默认 20） | 工具只能拿到第 1 页的 20 条 |
| `kg_feign_chain`、`kg_mq_chain` 不发 `maxDepth`；后端默认 10 | 无法调整追踪深度 |
| `kg_bridges` 的 `nodeId` 未做 URL 编码，与 `kg_blast_radius` 的做法不一致 | 含特殊字符的节点 ID 可能导致路径错误 |
| `kg_hotspots` 的 `limit`、`kg_blast_radius` 的 `maxDepth` 用真值判断 | 传 `0` 时参数不会发出，落到后端默认值（20 / 5） |
| 多个路径用逗号拼成一个参数 | 路径本身含逗号时会被拆开 |
| 文件头与定义区的注释仍写 15 个工具 | 只影响阅读 |

| 扩展点 | 扩展方式 |
|--------|---------|
| 新增一个知识图谱工具 | 加一条定义、`KG_TOOLS` 加名字、类里加方法、`switch` 加分支 |
| 暴露 `entry-points` 的分页 | 在 `entryPoints()` 的 `base` 里加 `page` / `pageSize`，并在 schema 声明 |
| 让新工具受项目范围约束 | 在 `scopeManager.ts` 的 `TOOL_SCOPE_REGISTRY` 登记 |
