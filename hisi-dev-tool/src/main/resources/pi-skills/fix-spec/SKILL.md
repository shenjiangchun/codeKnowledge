# 修复 Spec 生成

输入是已确认的修复方案与待办证据。

## 要求

- 目标：一句话说清修什么、为什么。
- 验收标准：可检验（改了哪个行为、哪个输入产生哪个输出）。
- 测试用例：**在 Spec 阶段就定死**，每条给类型（unit/api/e2e）、名称、落点（类/接口）、通过标准；这是后续开发与回归的验收依据，不得在后续阶段放宽。
- 非目标：明确列出不做什么（防止修复蔓延）。
- 涉及接口时给出 HTTP 方法、路径、参数与返回的现状。
