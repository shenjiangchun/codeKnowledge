## 1. 模块概述

## 2. 模块架构

### 2.1 写法约定

11 个 Store 中有 10 个采用**组合式写法**（`defineStore(id, () => { ... })`，内部用 `ref` / `computed` 表示状态与派生值），只有 `workbench` 采用**选项式写法**（`state` + `actions` 对象）。

每个组合式 Store 都以一个显式的 `return { ... }` 对象结尾，并按"State / Computed / Actions"分段注释，这就是该 Store 的对外接口清单。

### 2.3 Store 之间的依赖

Store 彼此之间不直接互相引用，唯一的例外是 `utils/request.ts` 在收到 401 时动态导入 `auth` Store 弹出登录框。跨 Store 的"联动"都发生在组件层，例如 `useDagEventHandler` 在处理影响分析结果时调用 `useRamStore().setImpact`。

`apmStore` 是唯一在内部组合了 Composable 的 Store：它在 setup 函数里调用 `useApmWebSocket()`，把 WebSocket 的六个状态直接作为自己的状态导出。

### 3.2 `useAppStore`

| 分类 | 成员 |
|------|------|
| 状态 | `projectDir`、`selectedProjects`（`{ name, path }[]`）、`configLoading`、`configError` |
| 派生 | `projectDirConfigured`、`projectSelected`、`selectedProject`（首个选中项目名，向后兼容）、`selectedProjectNames`、`availableMenus` |
| 动作 | `loadProjectDir`、`updateProjectDir`、`selectProjects`、`selectProject`、`clearSelectedProject`、`getSelectedProjectPaths` |

`selectedProjects` 上挂了一个深度 `watch`，任何变更都会写回 `localStorage`，Store 创建时再从那里恢复。

`availableMenus` 是一个对象，键为菜单标识，值为布尔。注释明确说明：`projectDirConfigured` **不**参与判定（远程项目可以没有本地扫描根目录），只有 `projectSelected` 会影响 `search`、`knowledge-graph`、`architecture-diagnosis` 三个键；其余键恒为 `true`。

### 3.3 `useAuthStore`

详见 [认证与系统管理](./认证与系统管理.md)。

### 3.4 `usePromptStore`

| 分类 | 成员 |
|------|------|
| 状态 | `templates`（`PromptTemplate[]`）、`loading` |
| 动作 | `loadTemplates`、`getTemplate(key)`、`updateTemplate(key, content, variables?)`、`render(key, variables)`、`extractVariables(content)` |

`render` 在前端完成变量替换，占位符语法是 `#{变量名}`；变量名需匹配 `[a-zA-Z_][a-zA-Z0-9_]*`。模板不存在时返回空字符串并打 `console.warn`。`api/prompt.ts` 里另有服务端渲染与变量提取接口，但 Store 没有调用它们。

### 3.5 `useRamStore`

| 分类 | 成员 |
|------|------|
| 状态 | `impact`（`ImpactPayload \| null`）、`lastSessionId`、`selectedFile`、`hoveredFile`、`highlightPath`（`Set<string>`） |
| 动作 | `setImpact(sessionId, payload)`、`clear`、`selectFile`、`hoverFile`、`setHighlightPath(files)`、`clearHighlight` |

文件头注释说明它刻意保持很小：`impact` 只用于在草稿页与图谱预览页之间传递影响数据，长期会话状态归 `useRamSession` 所有。后四个成员服务于图谱与文件列表的双向联动，图谱页卸载时会主动清空以免泄漏到其它页面。

### 3.6 `useRamChatStore`

| 分类 | 成员 |
|------|------|
| 状态 | `sessions`（`SessionSummary[]`）、`currentSessionId`、`events`（`ChatEvent[]`）、`loading`、`error`、`isStreaming` |
| 动作 | `fetchSessions`、`createSession(projectPaths, projectName)`、`selectSession`、`sendMessage(text)`、`appendEvent(event)`、`interrupt`、`renameSession`、`deleteSession` |

`sendMessage` 根据当前是否在流式输出选择接口：流式中调用 `injectMessage`（插话），否则调用 `sendMessage`。`appendEvent` 是 WebSocket 事件的唯一入口，它按事件类型维护 `isStreaming`：收到 `ASSISTANT_DELTA` 置真，收到 `CHECKPOINT` 或 `TURN_INTERRUPTED` 置假。

### 3.7 `useWorkbenchStore`

详见 [工作台](./工作台.md)。

### 3.8 `useWorkspaceStore`

| 分类 | 成员 |
|------|------|
| 状态 | `sessions`（`ClaudeWorkspaceSession[]`）、`currentSessionId`、`loading` |
| 派生 | `currentSession`、`activeSessions`、`archivedSessions` |
| 动作 | `loadSessions(status?)`、`createSession(scene?, initialPrompt?, workingDirectory?)`、`updateSession`、`deleteSession`、`archiveSession`、`bindClaudeSession`、`selectSession` |

`loadSessions` 在重新拉取后会检查原先选中的会话是否仍存在，不存在则把 `currentSessionId` 置空。各写操作失败时弹出"创建会话失败"等提示，`createSession` 失败还会把异常继续抛出。

### 3.9 `useSessionStore`

| 分类 | 成员 |
|------|------|
| 状态 | `sessions`（`Session[]`）、`currentSessionId`、`messages`（`Message[]`）、`loading`、`total`、`streamingSessionId`、`isStreaming` |
| 未导出的内部状态 | `messagesCache`、`streamingContentCache`、`streamingStatusCache`（均以 `sessionId` 为键） |
| 派生 | `currentSession`、`activeSessions`、`archivedSessions` |
| 动作 | 会话：`loadSessions(status?, page = 1, pageSize = 20)`、`loadSessionDetail`、`setCurrentSession`、`switchSession`、`updateSessionTitle`、`archiveSession`、`deleteSession`、`clearSessionMessages`、`exportSession`、`closeSession`、`resumeSession` |
| 动作 | 流式：`setStreamingSession`、`appendStreamingContent`、`appendStreamingContentLegacy`、`clearStreamingContent`、`clearCurrentStreamingContent`、`getStreamingContent`、`isSessionStreaming` |
| 动作 | 消息：`addMessageToSession`、`addMessage`、`clearCurrentMessages` |

这是状态最多、动作最多的 Store。要点：

- 消息与流式内容都按会话隔离缓存，切换会话时优先用缓存，避免重复请求。
- `switchSession` 只清前端的流式显示状态，**不关闭后端会话**，进行中的会话在后台继续；若新会话带 `claudeSessionCode`，会非阻塞地调用恢复接口。
- 带 `Legacy` 后缀的两个动作作用于"当前会话"，注释标明是兼容旧接口。
- `exportSession` 下载文件名固定为 `session-{id}.{format}`。

### 3.10 `useSkillStore`

| 分类 | 成员 |
|------|------|
| 状态 | `skills`（`SkillDefinition[]`）、`projectStatus`（`ProjectSkillStatus[]`）、`loading`、`statusLoading`、`selectedCategory`、`searchKeyword`、`categoryStats`、`totalSkills` |
| 派生 | `filteredSkills`（按分类与关键词过滤）、`installedSkillIds`（`Set`） |
| 动作 | `loadSkills`、`loadProjectStatus(projectDir)`、`installSkill(skillId, projectDir)`、`uninstallSkill(skillId, projectDir)`、`isSkillInstalled`、`isSkillOperating`、`getSkillInstallStatus`、`setCategory`、`setSearchKeyword`、`clearFilters` |

安装 / 卸载返回布尔值表示是否成功，成功后会重新拉取项目技能状态。关键词匹配范围是名称、描述与标签。

### 3.11 `useThemeStore`

| 分类 | 成员 |
|------|------|
| 状态 | `themeId`（默认 `dark-tech`）、`customAccent`（`string \| null`） |
| 派生 | `presets`、`currentTheme`、`isDark` |
| 动作 | `setTheme(id)`、`setCustomAccent(color)`、`resetToDefault`、`getTerminalTheme`、`init` |

- 预设主题 6 套：`dark-tech` 深色科技（默认）、`dark-monokai` Monokai 经典、`dark-dracula` Dracula、`light-minimal` 浅色简约、`light-sepia` 护眼暖色、`eye-care` 护眼绿色。
- 每次切换都会把主题里的 16 个颜色值写入 `document.documentElement` 的 CSS 变量，因此主题对整个应用生效，不只是终端。
- 自定义主色调通过复制一份主题并覆盖 `accentPrimary` 与终端光标色实现，不修改预设本身。
- `getTerminalTheme()` 返回给 xterm.js 用的颜色对象。

### 3.12 `useApmStore`

| 分类 | 成员 |
|------|------|
| WebSocket 状态 | `wsConnected`、`wsSpans`、`wsEvents`、`wsProcessStatus`、`wsProcessLogs`、`wsProcessError` |
| 状态 | `projects`、`selectedProject`、`sessionId`、`serviceName`、`targetPort`、`status`、`errorMessage`、`projectsLoading`、`activeSessions`、`entryPoints`、`selectedEntry`、`entryPointsLoading`、`instrumentationMode`、`bodySchema`、`bodySchemaLoading`、`requestConfig`、`lastResponse`、`report`、`selectedSpan` |
| 派生 | `traceTree`、`isActive`、`canExecute`、`showTracePanel` |
| 动作：项目与入口 | `loadProjects`、`loadActiveSessions`、`forceStopSession`、`selectProject`、`loadEntryPoints`、`selectEntry` |
| 动作：请求编辑 | `addQueryParam`、`removeQueryParam`、`updateQueryParam`、`setHeaders`、`setBody`、`setMethod`、`setUrl` |
| 动作：会话生命周期 | `launchSession`、`executeRequest`、`stopSession`、`fetchReport`、`handleWsEvent` |
| 动作：界面 | `selectSpan`、`resetRequest`、`resetAll`、`cleanup`、`clearProcessConsole` |

状态取值 `ApmSessionStatus`：`IDLE` → `LAUNCHING` → `READY` → `EXECUTING` → `STREAMING` → `COMPLETE`，任一步失败进入 `ERROR`。Store 内部 `watch(wsEvents)`，在 `STREAMING` 状态下收到 `EXECUTION_COMPLETE` 时自动拉取报告。详见 [APM调试](./APM调试.md)。

## 6. 错误处理

| Store | 策略 |
|-------|------|
| `app` | `loadProjectDir` 失败把异常消息写入 `configError`；`updateProjectDir` 返回 `false` |
| `auth` | `init` 失败即清空身份；`login` / `register` 不捕获，交由调用方提示 |
| `prompt` | 加载与更新失败仅 `console.error`，不改变状态 |
| `ramChat` | `fetchSessions` 失败把消息写入 `error`；`interrupt` 失败仅打日志；其余抛出 |
| `workbench` | `load` 用 `try / finally` 保证 `loading` 复位，异常向上抛 |
| `workspace` | 写操作失败弹出 Element Plus 错误提示；`createSession` 额外抛出 |
| `session` | 全部动作自行捕获并 `console.error`，调用方不会收到异常 |
| `skill` | 加载技能列表失败弹错误提示，不改状态；加载项目状态失败弹提示并把状态置空；安装 / 卸载返回 `false` |
| `apm` | 依赖请求拦截器提示；启动与执行失败把 `status` 置 `ERROR` 并写 `errorMessage` |

## 7. 性能考量

| 关注点 | 策略 | 实现 |
|--------|------|------|
| 避免重复加载 | `loaded` 标志与 `loading` 互斥 | `workbench.load` |
| 消息缓存 | 按 `sessionId` 缓存，切换会话先查缓存 | `sessionStore.messagesCache` |
| 日志缓冲上限 | 超过 2000 行裁到 1500 行 | `useApmWebSocket`（经 `apmStore` 导出） |
| 路径归一化 | 统一把反斜杠换成正斜杠 | `appStore.getSelectedProjectPaths` |

## 8. 已知问题与扩展点

| 类型 | 说明 |
|------|------|
| 已知问题 | `useApmWebSocket` 内部注册了 `onUnmounted`；据 `ApmDebugView` 中的注释，它在 Pinia Store 的上下文中不会触发，因此该视图在卸载时显式调用 `store.cleanup()` |
| 已知问题 | `sessionStore` 的 `appendStreamingContentLegacy`、`clearCurrentStreamingContent`、`addMessage`、`clearCurrentMessages` 四个动作在代码中没有找到调用方（`ClaudeSession.vue` 用的是按会话编号传参的版本） |

| 扩展点 | 新增 Store：在 `src/stores/` 下建文件并沿用"组合式写法 + 末尾显式 return"的约定即可，无需在 `index.ts` 注册 |
