## 3. 鉴权与角色

### 3.1 链路

```mermaid

    REQ["HTTP 请求"]:::entry
    CORS["CorsFilter"]:::process
    JWT["JwtAuthFilter<br/>解析 Bearer 或 ?token="]:::process
    CTX{{"令牌有效 ?"}}:::dec
    ATTR["request attribute<br/>SecurityContext(username, role)"]:::data
    ADM["AdminOnlyInterceptor"]:::entry
    CTL["Controller"]:::process
    E401["HTTP 401 / 403"]:::ext

    REQ --> CORS --> JWT --> CTX
    CTX -->|是| ATTR --> ADM --> CTL
    CTX -->|否或无令牌| ADM
    ADM -->|不满足| E401

    classDef entry fill:#1565c0,stroke:#0d47a1,color:#fff
    classDef process fill:#e3f2fd,stroke:#1976d2,color:#0d47a1
    classDef dec fill:#fff8e1,stroke:#f57c00,color:#e65100
    classDef data fill:#e8f5e9,stroke:#388e3c,color:#1b5e20
    classDef ext fill:#fce4ec,stroke:#c62828,color:#b71c1c
```

- `JwtAuthFilter` 挂在 `/*`，顺序 `HIGHEST_PRECEDENCE + 10`。先看 `Authorization: Bearer <token>`，没有再取查询参数 `token`（SSE / EventSource 设不了请求头）。**令牌无效时不拒绝请求**，只是不设置身份。
- `SecurityContext` 是请求属性，`isAdmin()` 即 `role == "ADMIN"`。
- 真正的拒绝发生在 `AdminOnlyInterceptor`（挂在 `/**`）。

### 3.2 拦截规则

| 请求 | 规则 |
|------|------|
| `OPTIONS` | 放行 |
| 路径以 `/api/auth/`、`/api/search/`、`/api/vector-search/`、`/api/ram/` 开头 | 不经过拦截器，无需登录 |
| 路径以 `/api/workflow/`、`/api/v2/workflow/`、`/api/workbench/` 开头 | **所有方法**都要登录；未登录返回 HTTP 401 |
| 其余 `GET`（`/api/users` 开头除外） | 放行 |
| 其余非 `GET`，以及 `/api/users` 开头的 `GET` | 未登录返回 HTTP 401；已登录但不是 `ADMIN` 返回 HTTP 403 |

拒绝时响应体为 `ApiResponse`：`{"code": 401, "message": "请先登录后再执行此操作", "data": null}` 或 `{"code": 403, "message": "仅管理员可执行此操作", "data": null}`，HTTP 状态码与 `code` 一致。

### 3.3 令牌 `JwtTokenProvider`

| 项目 | 规则 |
|------|------|
| 算法 | JJWT `Keys.hmacShaKeyFor` + `parseSignedClaims` |
| 载荷 | `subject` = 用户名，`role` 声明，签发与过期时间 |
| 有效期 | `jwt.expiration-ms`（`application.yml` 中 86400000，即 24 小时） |
| 密钥 | `jwt.secret`（环境变量 `JWT_SECRET`）；配置值不足 32 字节则启动抛 `IllegalStateException` |
| 未配置密钥 | 每次启动随机生成并打印告警；重启后已签发令牌全部失效 |

### 3.4 账号

| 端点 | 说明 |
|------|------|
| `POST /api/auth/login` | 请求体 `{username, password}`；成功返回 `{token, username, role}`；失败返回 `code=401` |
| `POST /api/auth/register` | 开放注册，角色固定 `MEMBER`；用户名 2–32 字符、口令至少 4 位；重名返回 `code=409` |
| `GET /api/auth/me` | 返回 `{username, role}`，未登录返回 `data=null` |
| `GET /api/users` | 用户列表（需管理员） |
| `PUT /api/users/{id}/role` | 改角色，`role` 只能是 `ADMIN` 或 `MEMBER`（需管理员） |

口令用 BCrypt 存储。首次启动且 `sys_user` 中没有 `root` 时创建 `root`（`ADMIN`）：初始口令取 `hisi.auth.root-password`（环境变量 `HISI_ROOT_PASSWORD`），未配置则随机生成并打印在启动日志里。

### 3.5 WebSocket 握手

`JwtHandshakeInterceptor` 实现了从 `?token=` 校验令牌的握手拦截，但 `WebSocketConfig` 注册的 7 个端点挂的都是 `HttpSessionHandshakeInterceptor`，主代码中没有其他地方使用它。即：按当前代码，WebSocket 握手不做令牌校验。

## 4. 统一响应与异常

### 4.1 `ApiResponse<T>`

`model/ApiResponse`：字段 `code`（200 成功）、`message`、`data`；静态方法 `success(data)`、`error(code, message)`、`error(message)`（默认 500）；`isSuccess()` 即 `code == 200`。`JacksonConfig` 把 `Long` / `long` 一律序列化为字符串（避免雪花 ID 超出 JS 安全整数范围）。

### 4.2 `GlobalExceptionHandler`

| 异常 | HTTP 状态 | 响应体 |
|------|---------|-------|
| `MethodArgumentNotValidException` | 400 | `ApiResponse.error(400, "参数校验失败: ...")` |
| `IllegalArgumentException` | 400 | `ApiResponse.error(400, ex.getMessage())` |
| `MissingServletRequestParameterException` | 400 | `ApiResponse.error(400, "缺少必需参数: <参数名>")` |
| `SearchException` | 取自 `SearchErrorCode.getHttpStatus()` | `ApiResponse.error(code, userMessage)` |
| 其他 `RuntimeException` | 500 | `ApiResponse.error(500, "服务内部错误: ...")` |
| 其他 `Exception` | 500 | SSE 请求或路径含 `/stream`、`/chat` 时返回纯文本「服务异常: ...」，否则 `ApiResponse.error(500, ...)` |
| `HttpMessageNotWritableException` | 500 | 同上的纯文本 / `ApiResponse` 分支 |

流式接口上客户端断开（异常链含 `AsyncRequestNotUsableException`，或 `/stream` 路径上的 `IOException`）不算服务端错误：按 debug 记录且不再写响应。

写日志时查询串里的 `token`、`access_token`、`password`、`passwd`、`secret`、`api_key`、`authorization` 会被替换为 `***`。

## 11. 错误处理

| 场景 | 处理 |
|------|------|
| 未登录访问受保护接口 | HTTP 401，`ApiResponse(code=401)` |
| 非管理员执行写操作 | HTTP 403，`ApiResponse(code=403)` |
| JWT 密钥短于 32 字节 | 启动失败（`IllegalStateException`） |

| 流式接口客户端断开 | 不写响应，debug 日志 |
| pi 安装失败 | 不阻断启动 |

## 12. 已知问题与扩展点

| 问题 | 说明 |
|------|------|
| WebSocket 握手未校验令牌 | `JwtHandshakeInterceptor` 已实现但未挂载 |
| 允许循环依赖 | `spring.main.allow-circular-references=true`，源码注释为临时方案 |
| pom 仍声明 Spring AI 依赖 | 主代码零引用，靠 `spring.autoconfigure.exclude` 排除自动配置 |
| 错误语义不统一 | 拦截器用真实 HTTP 状态码；多数业务接口 HTTP 200、错误看 `code` |
| `application-local.yml` 仍含 `spring.ai.*` 段 | 主代码已不读取该段（属本机文件内容，随部署而异） |
| 敏感配置分散 | 密钥类配置有环境变量与本机文件两条路径，缺少统一的必填校验 |

| 扩展点 | 方式 |
|-------|------|
| 新增需要登录 / 管理员的路径 | 在 `AdminOnlyInterceptor.preHandle` 增加路径前缀规则 |
| 新增 WebSocket 端点 | 实现 `WebSocketHandler`，在 `WebSocketConfig.registerWebSocketHandlers` 注册 |
| 新增启动期任务 | `@PostConstruct`（建表类）或 `ApplicationReadyEvent`（依赖图数据库的初始化） |
