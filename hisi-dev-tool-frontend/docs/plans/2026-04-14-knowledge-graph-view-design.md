# 知识图谱分析页面设计

> **日期**: 2026-04-14
> **状态**: 已确认
> **目标**: 创建综合型知识图谱分析页面，支持问题定位、代码理解、影响评估三种场景

## 背景

当前系统已有调用链生成功能，但仅覆盖 HTTP 入口。知识图谱模块已完成后端数据生成，支持 HTTP/MQ/定时任务/事件监听/WebSocket/RPC 等多种入口类型，但前端缺乏消费这些数据的分析页面。

## 设计目标

创建统一的知识图谱分析页面，通过 Tab 切换支持三种核心场景：
1. **问题定位** - 从任意方法出发，快速找到相关入口
2. **代码理解** - 全局视角浏览项目结构
3. **影响评估** - 修改某方法前，分析影响范围

## 页面结构

```
┌─────────────────────────────────────────────────────────────┐
│  知识图谱分析                              [项目选择器]       │
├─────────────────────────────────────────────────────────────┤
│  [问题定位] [代码理解] [影响评估]                            │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│                    (Tab 内容区域)                            │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

## Tab 1: 问题定位

### 场景
从任意方法出发，快速找到相关入口（HTTP/MQ/定时任务/事件等）

### 布局
```
┌─────────────────────────────────────────────────────────────┐
│ 搜索方法: [com.example.Service.process    ] [搜索]          │
├─────────────────────────────────────────────────────────────┤
│ ┌─────────────────────┐  ┌───────────────────────────────┐  │
│ │ 关联入口点 (5)       │  │ 调用链详情                    │  │
│ │ ─────────────────── │  │ ─────────────────────────────  │  │
│ │ 🌐 POST /api/order  │  │ 入口: OrderController.create  │  │
│ │ ⏰ 定时任务 syncData │  │ ─────────────────────────────  │  │
│ │ 📨 MQ order.queue   │  │ [树形/流程图 切换]             │  │
│ │ ...                 │  │                               │  │
│ │                     │  │   OrderController.create      │  │
│ └─────────────────────┘  │       └─ OrderService.create   │  │
│                          │           └─ Service.process ✓ │  │
│                          └───────────────────────────────┘  │
└─────────────────────────────────────────────────────────────┘
```

### 核心功能
1. 方法搜索（支持类名.方法名模糊匹配）
2. 显示所有关联入口（HTTP/MQ/定时任务/事件等）
3. 点击入口展开完整调用链

### API 使用
- `getCallChainsAffecting(className, methodName, projectPath)` - 反向查询入口
- `getCallChainByKey(entryKey, projectPath)` - 获取调用链详情
- `getMethodsByClass(className, projectPath)` - 方法搜索辅助

## Tab 2: 代码理解

### 场景
全局视角浏览项目结构，理解入口分布

### 布局
```
┌─────────────────────────────────────────────────────────────┐
│ 入口类型: [全部 ▼]  统计: 160 入口 | 3133 方法 | 1627 调用   │
├─────────────────────────────────────────────────────────────┤
│ ┌─────────────────────┐  ┌───────────────────────────────┐  │
│ │ 入口点列表          │  │ 入口详情                       │  │
│ │ ─────────────────── │  │ ─────────────────────────────  │  │
│ │ 类型  │ 入口标识    │  │ POST /api/orders               │  │
│ │ ─────────────────── │  │ Controller: OrderController   │  │
│ │ 🌐 HTTP │ /api/users│  │ 方法: createOrder()            │  │
│ │ 🌐 HTTP │ /api/order│  │ 深度: 6 层                     │  │
│ │ ⏰ SCHED│ syncData  │  │ 调用方法数: 45                 │  │
│ │ 📨 MQ   │ order.q   │  │ ─────────────────────────────  │  │
│ │ ...                 │  │ [查看调用链] [AI 分析]         │  │
│ └─────────────────────┘  └───────────────────────────────┘  │
└─────────────────────────────────────────────────────────────┘
```

### 核心功能
1. 按入口类型筛选（HTTP/MQ/SCHEDULED/EVENT/RPC/WEBSOCKET）
2. 入口点列表，显示基本信息
3. 点击查看详细调用链
4. 统计面板（入口数/方法数/调用关系数）

### API 使用
- `getEntryPoints(projectPath, entryType)` - 获取入口点列表
- `getCallChainByKey(entryKey, projectPath)` - 获取调用链详情
- `getStatus(projectPath)` - 获取统计数据

## Tab 3: 影响评估

### 场景
修改某方法前，分析影响范围，评估风险

### 布局
```
┌─────────────────────────────────────────────────────────────┐
│ 分析目标: [com.example.OrderService.updateStatus] [分析]    │
├─────────────────────────────────────────────────────────────┤
│ ┌─────────────────────────────────────────────────────────┐ │
│ │ 影响范围概览                                             │ │
│ │ ─────────────────────────────────────────────────────── │ │
│ │ 影响入口数: 8 个                                         │ │
│ │ 调用层级: 最深 5 层                                      │ │
│ │ 风险等级: ⚠️ 中等风险                                    │ │
│ └─────────────────────────────────────────────────────────┘ │
│                                                             │
│ ┌─────────────────────────────────────────────────────────┐ │
│ │ 受影响入口列表                                           │ │
│ │ ─────────────────────────────────────────────────────── │ │
│ │ 🌐 POST /api/orders/create      │ 层级: 3 │ [查看链路]  │ │
│ │ 🌐 PUT  /api/orders/{id}/status │ 层级: 2 │ [查看链路]  │ │
│ │ ⏰ 定时任务 orderSync           │ 层级: 4 │ [查看链路]  │ │
│ │ ...                                                      │ │
│ └─────────────────────────────────────────────────────────┘ │
│                                                             │
│ [导出报告] [AI 生成影响分析]                                 │
└─────────────────────────────────────────────────────────────┘
```

### 核心功能
1. 反向追踪：从方法找到所有调用入口
2. 影响范围统计
3. 风险等级评估（基于入口数、调用层级）
4. 支持 AI 分析

### API 使用
- `getCallChainsAffecting(className, methodName, projectPath)` - 反向查询
- `getMethodDetail(nodeId, projectPath)` - 获取方法详情
- `getCallers(className, methodName, projectPath)` - 获取调用者

## 实现优先级

1. **P0 - Tab 2 代码理解** - 最基础，直接展示入口点列表
2. **P1 - Tab 1 问题定位** - 核心功能，反向查询
3. **P2 - Tab 3 影响评估** - 增强，加入 AI 分析

## 风险评估

| 风险 | 影响 | 缓解措施 |
|-----|------|---------|
| 大型项目数据量大 | 前端渲染性能 | 分页加载、虚拟滚动 |
| 方法搜索匹配不准 | 用户体验差 | 支持模糊匹配、类名前缀匹配 |
| 调用链层级过深 | 展示混乱 | 折叠展示、深度限制 |

## 验收标准

1. 能搜索任意方法并显示关联入口
2. 能按入口类型筛选浏览入口点
3. 能分析修改某方法的影响范围
4. 调用链展示支持树形和流程图两种视图
5. 支持跳转到代码位置（IDE 集成）
