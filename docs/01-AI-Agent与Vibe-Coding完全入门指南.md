## 第 1 章：先搞清楚 AI 是怎么回事

> 本章阅读时间：约 10 分钟

### 1.1 什么是大语言模型（LLM）？

**一句话解释：大语言模型就是一个"超级读书机器人"，它读遍了互联网上几乎所有文字，然后学会了"接话"。**

打个比方。你朋友说"今天天气真——"，你脑子里会自动蹦出"好""热""差"这些词。大语言模型（英文叫 Large Language Model，简称 LLM）做的事情本质上就是这个——只不过它不是凭感觉，而是读了几万亿字的文章、书籍、代码、对话之后，统计出了"在什么情况下，下一个词最可能是什么"。

ChatGPT 就是最出名的大语言模型。你问它一个问题，它根据自己读过的海量文字，一个字一个字地"接"出一个回答。

你可能会问："这听起来不就是个高级的'输入法联想'吗？"

确实，从数学原理上说，它就是在做"下一个词预测"。但当模型足够大、读的数据足够多的时候，这种简单的预测能力会涌现出让人惊讶的能力——它能理解你的问题、能写诗、能翻译、能写代码、能帮你分析数据。

**你可以把它想象成一个读过整个图书馆的人。** 你问它什么，它都能从"记忆"中找出相关信息来回答你。

### 1.2 什么是 Prompt？

**一句话解释：Prompt 就是你跟 AI 说的话。**

你在 ChatGPT 输入框里打的每一个字，就是 Prompt。中文翻译叫"提示词"，但我更喜欢叫它"指令"——因为本质上，你是在给 AI 下达指令。

Prompt 可长可短：
- 短的："用通俗的话解释一下什么是区块链。"
- 长的：你可以给 AI 发一整页文档，然后说"帮我总结这篇文章的三个核心观点"。

Prompt 的质量直接影响 AI 回答的质量。就像你跟一个人说话，说"帮我做点事"和"帮我把这 50 页的报告整理成 3 个要点的 PPT"，对方干出来的活肯定不一样。

好消息是，2026 年的 AI 已经聪明到不需要你写什么"专业提示词"了。用大白话说清楚你想干什么，就够了。

### 1.3 AI 能做什么、不能做什么

**能做什么：**

- 回答问题和解释概念："什么是黑洞？用中学生能听懂的话解释。"
- 写作：写邮件、写报告、写文案、写故事
- 翻译：中英互译已经很流畅
- 写代码：从简单的网页到复杂的后端系统
- 分析数据：上传表格，让它找规律、做总结
- 头脑风暴：帮你出主意、列方案

**不能做什么（目前）：**

- 真正"理解"世界：AI 没有意识、没有情感、没有真实体验。它只是模式匹配，不是真的"懂"。
- 100% 准确：AI 会"编造"信息（行话叫"幻觉"）。它有时会自信地说出完全错误的东西。
- 替代人类的判断力：AI 可以给建议，但不能替你做决定——尤其是在涉及伦理、安全、法律的事情上。
- 处理最新事件（如果不联网）：大部分模型的知识有截止日期，不知道今天发生了什么。

**一个重要的认知：** AI 是一个超级工具，而不是一个超级大脑。把它想象成一个能力超强的实习生——它能帮你做很多事情，但你得知道怎么安排任务、怎么检查结果。

## 第 2 章：AI Agent —— 不止是聊天机器人

> 本章阅读时间：约 15 分钟

### 2.1 聊天机器人 vs AI Agent

**一句话解释：聊天机器人是"你问一句它答一句"的问答机器；而 AI Agent 是"你给一个目标，它自己想办法完成"的智能助手。**

用"查天气"这个例子来说明区别：

- **聊天机器人**：你问"今天天气怎么样？"它凭自己的"记忆"（训练数据）回答你。这个回答可能过时了、可能不准确，因为它并没有真的去查天气。
- **AI Agent**：你问"今天天气怎么样？"它会自己去打开天气预报网站，查到真实数据，然后告诉你"今天北京晴，18 到 25 度"。

看出区别了吗？聊天机器人只能"说"，AI Agent 能"做"。

再举一个编程的例子：

- **聊天机器人**：你问"怎么写一个登录功能？"它给你一段代码，你自己复制粘贴。
- **AI Agent**：你说"给我的 App 加一个登录功能"。它自己去读你的项目代码，找到合适的位置，写好代码，甚至帮你测试一下能不能跑通。

这也是为什么 2026 年大家都在讨论 Agent 而不是聊天机器人——**Agent 能从"建议"变成"执行"**。

### 2.2 Agent 的"大脑"：ReAct 循环

**一句话解释：Agent 的思考方式是一个循环——"想一想接下来要做什么"、"动手去做"、"看看结果怎么样"、"根据结果再想想下一步"——不断重复直到任务完成。**

学术上叫 ReAct，是 Reasoning（推理）+ Acting（行动）的缩写。用大白话就是四个字：

```
想 → 做 → 看 → 再来
```

具体展开：

1. **想（Reason）**：Agent 接到你的任务后，先分析"要完成这个目标，我需要做什么？"
2. **做（Act）**：然后调用工具去执行——可能是搜网页、查数据库、写代码、发邮件……
3. **看（Observe）**：拿到结果后，检查"这一步做对了吗？还需要什么？"
4. **再来（Repeat）**：如果任务没完成，回到第一步继续。

**你可以想象成你点外卖的过程**：你想吃宫保鸡丁（目标）→ 打开外卖 App 搜索（行动）→ 看到几家店，比较评分和价格（观察）→ 选一家下单（行动）→ 看到订单确认（观察）→ 任务完成。这就是一个简化版的 ReAct 循环。

2026 年学术研究发现，Agent 失败的原因往往不是模型不够聪明，而是这个循环设计得不好——要么不会停（死循环），要么工具用错了，要么没有兜底方案。

### 2.3 生活中的 Agent

Agent 这个概念其实离你不远。你已经在用了：

| Agent 类型 | 代表产品 | 能做什么 |
|-----------|---------|---------|
| **AI 编程助手** | Claude Code、Cursor、GitHub Copilot | 你描述需求，它帮你写代码、修 bug、重构项目 |
| **智能客服** | 各种客服机器人 | 不只是回答"退货政策"，而是真的帮你查订单、发起退款 |
| **自动驾驶** | 特斯拉 FSD、小鹏 XNGP | 感知环境、规划路线、控制车辆——真正在物理世界行动 |
| **智能家居** | 小米智能家庭 | 不只是"开灯"，而是"检测到主人回家了，自动开灯、开空调、放音乐" |

### 2.4 一个完整的 Agent 由哪几部分组成

**一句话解释：可以把 Agent 想象成一个人——有大脑（思考）、有手（做事）、有记忆（记住做过什么）。**

三层结构：

```
大脑（推理引擎）
  ↓ 决定做什么
手（工具调用）
  ↓ 去执行
记忆（状态管理）
  ↓ 记住上下文
  ↑
  └── 反馈回来，形成循环
```

- **大脑（推理引擎）**：就是大语言模型本身。它负责理解你的需求、制定计划、判断每一步该做什么。
- **手（工具调用）**：Agent 能操作的各种外部工具——搜索引擎、数据库、API 接口、文件系统、甚至浏览器。没有工具的 Agent 就是一个只会说话的聊天机器人。
- **记忆（状态管理）**：Agent 需要记住"我刚才做了什么"、"现在进展到哪一步了"、"之前出过什么错"。没有记忆的 Agent 就像金鱼，每次都要从头开始。

2026 年社区和学术界的共识是：**大脑（模型能力）已经够强了，但手（工具接口标准化）和记忆（跨对话持久化）还是薄弱环节**。

## 第 3 章：Vibe Coding —— 用大白话写代码

> 本章阅读时间：约 15 分钟

### 3.1 Andrej Karpathy 是谁？他为什么提出这个概念？

**一句话背景：Andrej Karpathy 是 AI 界的大神级人物，前特斯拉 AI 负责人、OpenAI 创始成员。2025 年初，他在社交媒体上发了一句话，引发了整个编程世界的震动。**

那句话的大意是：

> "一种新的编程方式正在出现，我叫它 'Vibe Coding'。你只管用自然语言描述需求，完全沉浸在'感觉'里，不用管代码细节。AI 负责把代码写出来，你只管说'这个感觉对'还是'这个感觉不对'。"

这个概念之所以能火，是因为他精准地命名了一个正在发生的变化：编程的门槛正在消失。

2025 年底，柯林斯词典将 "Vibe Coding" 评为年度词汇。到 2026 年，它已经从一个网络段子变成了实际的开发方式。

### 3.2 Vibe Coding 到底是什么？

**一句话解释：Vibe Coding 就是"你用大白话说你想要什么，AI 帮你写出能跑的代码，你来判断对不对"。**

Vibe 这个词在英文里是"氛围""感觉"的意思。Karpathy 用这个词的意思是——你写代码的时候不用纠结语法、不用管底层逻辑，你只需要"感受"这个软件对不对。

这是一个四步循环：

```
描述 → 生成 → 审核 → 迭代
  ↑                    |
  └────────────────────┘
```

1. **描述（Describe）**：用大白话说出你想要什么。比如"做一个深色主题的待办事项应用，能添加、删除、标记完成"。
2. **生成（Generate）**：AI 在几十秒内写出完整代码。你不需要看每一行，第一次只要有东西跑起来就行。
3. **审核（Review）**：检查 AI 做的东西——功能对吗？有 bug 吗？安全吗？这里才是你花时间最多的地方。
4. **迭代（Iterate）**：告诉 AI 改什么。"把删除按钮改成红色""加一个已完成计数""这个页面太丑了，换一种风格"。

**关键认知**：Reddit 社区给 Vibe Coding 下了一个粗暴但精准的定义——**"Vibe Coding 就是你不读代码的时候。"**

反过来，如果你 review 了代码、写了测试、理解了逻辑——那你就不是在 Vibe Coding 了，你在正经做软件工程。Vibe Coding 是入门方式，不是终点。

### 3.3 一个真实例子：小白如何一天做出一个 App

假设你是一个完全不会编程的人，你想做一个"个人读书笔记工具"。

**早上 9 点**：打开 Lovable（浏览器里打开就行，不用装任何东西），在输入框里打字：

> "做一个读书笔记应用。用户可以添加书名，为每本书添加笔记，标记阅读进度（想读、在读、已读），界面用浅色简洁风格。"

**9 点 03 分**：Lovable 生成了一个完整的应用——有输入框、有书单列表、有进度标记。虽然界面比较简陋，但是功能已经能跑了。

**9 点 10 分**：你继续提需求：

> "每本书加一个封面图片的显示位置。在页面顶部显示一个统计数字：总共多少本、在读多少本、已读多少本。"

**9 点 12 分**：AI 加上了统计面板和封面占位。

**上午 10 点**：经过七八轮迭代，你的读书笔记应用已经很像样了——有书单管理、有笔记编辑、有进度追踪、有统计面板。

**下午 2 点**：你让 AI 帮你加上用户登录功能（Lovable 内置了 Supabase 后端，不需要自己搭服务器）。

**下午 4 点**：一键发布。你的读书笔记应用有了一个公开链接，可以发给朋友用了。

你在一天之内，从零开始，做出了一个能用的 Web 应用。你一行代码都没写，但你完成了从"我有一个想法"到"我有一个产品"的全过程。

### 3.4 Vibe Coding 能做什么、不能做什么

Reddit 和 Hacker News 社区的讨论中形成了一个"红黄绿"安全分区共识：

**绿色区（放心用）**
- 原型和 MVP：验证想法，快速出东西给人看
- 内部工具：给自己公司用的后台管理系统
- 落地页和营销网站
- 样板代码、测试、文档
- 简单的 SaaS 功能

**黄色区（可以用，但要额外检查）**
- 涉及用户数据的功能（检查隐私和安全）
- 支付相关（必须人工审核每一行支付代码）
- 复杂的业务逻辑（AI 可能搞错边界情况）

**红色区（不能用 Vibe Coding）**
- 安全关键代码（密码、加密、权限验证）
- 医疗、航空、金融交易等安全攸关系统
- 需要法律合规的代码
- 你在学习新技术的时候（手写才能真学会）

**一个重要的数据**：研究发现，15-20% 的 AI 生成的认证相关代码存在安全漏洞。所以关于安全的东西，一定要人工审查。

### 3.5 健康的 AI 使用比例：70/30 法则

- **70% AI 辅助**：样板代码、测试、文档、重构
- **30% 纯人工**：架构设计、复杂逻辑、安全检查、代码审核

如果你是 95% 靠 AI，你可能在往代码里塞 bug。如果你是 20%，你又浪费了大量生产力。70/30 是 2026 年社区广泛认同的平衡点。

## 第 4 章：2026 年，这些东西为什么突然火了？

> 本章阅读时间：约 10 分钟

### 4.1 四个推动力量

**力量一：模型变强了**

2025-2026 年，大语言模型的能力出现了质的飞跃。用学术界的评估标准 SWE-bench 来看（这个测试衡量的是 AI 解决真实软件 bug 的能力），Claude Code 的得分达到了 80-95%——这意味着 AI 已经能解决绝大多数的实际编程问题。三年前这个数字还不到 10%。

**力量二：工具变好了**

2026 年，AI 编程工具进入"三国杀"时代。Claude Code、Cursor、GitHub Copilot 三强争霸，中国的 Trae、通义灵码、CodeBuddy 也在快速追赶。这些工具不再是"玩具"，而是能真正提升生产力的专业工具。

**力量三：成本降低了**

几年前，调用一次大模型的 API 要花几毛钱，做多步推理可能烧掉几十块。2026 年，模型推理成本大幅下降，很多工具提供了慷慨的免费额度。国产工具甚至全部免费（Trae、通义灵码、CodeBuddy、文心快码都是免费的个人版）。

**力量四：人人都能用了**

最关键的变化：你不需要学编程就能用这些工具。Lovable、Bolt.new、Replit 这些"浏览器端 AI 应用生成器"把门槛降到了——会打字就行。

### 4.2 AI 编程工具市场份额变化

2026 年第一季度的数据（来源：Digital Applied，2847 名开发者调查）：

| 工具 | 主力工具份额 | 变化趋势 |
|------|:---------:|---------|
| **Claude Code** | 28% | 一年涨了 7 个百分点 |
| **Cursor** | 24% | 一年涨了 2 个百分点 |
| **GitHub Copilot** | 17% | 一年跌了 4 个百分点 |
| **OpenAI Codex CLI** | 11% | 一年涨了 3 个百分点 |
| **Windsurf** | 5% | 基本持平 |

Copilot 从 2024 年的绝对霸主（67%）滑落到 17%，不是因为它变差了，而是因为竞品变强了。**市场从"一家独大"变成了"百花齐放"**。

一个有趣的数据：开发者平均使用 **2.4 到 3.1 个** AI 工具。最主流的组合是"Cursor 做日常编码 + Claude Code 做大重构"。

### 4.3 "程序员不会被 AI 取代，但会用 AI 的程序员会取代不会用的"

这句话在 2026 年几乎成了行业共识。

数据支撑这个观点：
- **84%** 的开发者已使用或计划使用 AI 编程工具，但**只有 3%** "高度信任" AI 的输出
- 开发者平均花在审查 AI 代码上的时间（**每周 11.4 小时**）超过了写新代码的时间（每周 9.8 小时）
- 学术研究发现，AI 编程工具对**经验丰富的开发者提升最大**，对新手反而可能引入更多 bug

这说明了什么？**AI 是放大器，不是替代品。** 它放大的是你的判断力、经验、对业务的理解——而这些恰恰是 AI 没有的东西。

对于非程序员来说，这意味着：你的领域知识 + AI = 竞争力。一个懂医疗的产品经理用 AI 做出来的医疗 App，比一个不懂医疗的程序员手写的，可能更靠谱——因为产品经理知道什么是对的。

## 第 5 章：你的第一步 —— 今天就动手

> 本章阅读时间：约 10 分钟

### 5.1 零基础推荐第一步

你现在可能在想："说了这么多，到底应该怎么做？"

答案是：**打开一个工具，描述一个你想做的小东西，看看 AI 能帮你做出什么。**

动一次手比读十篇教程学得多。

#### 选择你的第一个工具

| 你的情况 | 推荐工具 | 为什么 |
|---------|---------|--------|
| 完全不会编程，想做 App | **Lovable** | 操作最简单，生成效果精美，有免费额度 |
| 完全不会编程，想最快出原型 | **Bolt.new** | 浏览器里直接跑，什么也不用装 |
| 想做微信小程序 | **Trae**（字节跳动） | 中文体验第一，免费，支持小程序开发 |
| 想边做边学编程 | **Replit** | 一个浏览器搞定代码+数据库+部署 |

**不要花一周比较工具。** 选一个，先打开用 10 分钟。工具之间的差异没有你想的那么大。

### 5.2 具体操作步骤（以 Lovable 为例）

**第 1 步**：打开浏览器，访问 lovable.dev，用 Google 或 GitHub 账号注册（免费）。

**第 2 步**：注册完成后，你会看到一个输入框。这就是你跟 AI 对话的地方。

**第 3 步**：在输入框中输入你的第一个 prompt（见下方的模板）。

**第 4 步**：等待 30-60 秒。AI 会生成一个完整应用的预览，你可以直接在浏览器里看到效果。

**第 5 步**：继续对话，提修改意见。比如：
- "把背景色改成深色"
- "加一个搜索框在页面顶部"
- "刚才的改动把布局搞乱了，撤销并用别的方法重做"

每次只加一个小功能，测试通过再加下一个。这样即使出错，你也知道是哪个改动导致的。

### 5.3 第一个 Prompt 模板

复制下面的模板，把方括号里的内容换成你自己的：

```
做一个【待办事项 / 读书笔记 / 习惯追踪 / 记账本】应用。

核心功能：
1. 【用户可以添加条目】
2. 【用户可以编辑和删除条目】
3. 【有一个列表展示所有条目】

风格要求：
- 【简洁 / 深色 / 极简】风格
- 按钮和文字要大一点，方便手机上操作

请做出一个完整可用的版本。
```

**几个建议：**
- 说清楚你想要什么，不要含糊
- 一次只描述 2-3 个功能，不要堆太多
- 如果 AI 理解错了，直接说"不对，我的意思是……"，它不会生气
- 遇到好的效果，记住你用了什么描述词

### 5.4 遇到问题怎么办

| 问题 | 解决方案 |
|------|---------|
| 生成的页面打不开 | 告诉 AI："页面打不开，检查一下有什么问题" |
| 功能跟我想的不一样 | 重新描述一次，用更具体的语言 |
| 改了一个功能，别的功能坏了 | 告诉 AI："刚才的改动把 XXX 搞坏了，撤销并换种方式重做" |
| ABC AI 对话超过 2-3 轮还是不对 | 换个思路描述，或者自己手动调整后让 AI 继续改 |
| 不知道接下来该做什么 | 让 AI 给建议："你觉得这个应用还能加什么有用的功能？" |
| 想看原理 | 问 AI："用通俗的话解释一下这段代码做了什么" |

**一个重要的安全提醒**：不要在 prompt 里透露任何敏感信息——密码、API 密钥、身份证号、银行卡号。你发给 AI 的内容会传到云端服务器。另外，如果你在做涉及用户登录、支付、隐私数据的应用，务必找懂技术的朋友帮你做安全检查。

### 5.5 一周入门计划

如果你有一个星期的时间，可以按这个节奏来：

| 天数 | 做什么 | 完成标志 |
|:----:|--------|---------|
| 第 1 天 | 在 Lovable 或 Bolt.new 上做一个"Hello World"页面 | 看到自己生成的网页 |
| 第 2 天 | 做一个完整的待办事项应用（添加、删除、标记完成） | 功能可以正常使用 |
| 第 3 天 | 给应用加分类、搜索、统计功能 | 找了 1-2 个朋友试用并给了反馈 |
| 第 4 天 | 做一个新项目——你自己想做的 | 核心功能跑通 |
| 第 5 天 | 继续迭代，优化界面和体验 | 应用看起来像样了 |
| 第 6 天 | 让 AI 解释你的代码，"这段代码做了什么？" | 能用通俗语言解释应用怎么跑起来的 |
| 第 7 天 | 一键发布，把链接发到朋友圈 | 收获第一批用户反馈 |

## 结语：你不是在学编程，你是在获得"从 0 到 1"的创造能力

这本书的名字叫"入门指南"，但它真正的目的不是让你"入门一个新领域"，而是让你意识到一件事：

**创造软件不再是程序员的特权。**

以前，你有一个想法——"我想做一个帮室友分账的小工具"——你要么得花几个月学编程，要么得花钱请人做。现在，你打开浏览器，说几句话，AI 帮你做出来。

当然，Vibe Coding 做出来的东西有局限——不适合处理敏感数据、不适合做复杂系统、安全和性能需要人工把关。但作为一个"想法验证工具"，它前所未有的强大。

2026 年社区的一个共识是：**Vibe Coding 适合原型，不适合生产。** 但这没关系——因为大多数好的产品，都是从原型开始的。

最后，分享一个故事。2026 年 3 月，一位 60 岁的程序员在 Hacker News 上发了一篇帖子，说 Claude Code 让他重新爱上了编程。他写道：

> "我从 1984 年开始写代码。经历过汇编、C、Java、Python 一个个时代。我以为编程的黄金时代已经过去了。直到我开始用 Claude Code——它让我感觉像一个指挥家，而不是一个打字员。"

编程的门槛在消失。指挥的能力比敲键盘的能力更重要。知道"我想要什么"比知道"怎么写出来"更重要。

**你的领域知识 + AI = 你的超能力。**

今天就开始吧。

## 附录：关键术语速查表

> 下表按"最可能先遇到的"顺序排列，越靠前越基础。每个术语附带一句话解释。

| 术语 | 中文名 | 一句话解释 |
|------|--------|-----------|
| **AI** | 人工智能 | 让计算机模拟人类智能的技术总称。你说的 AI 编程、AI Agent、AI 对话，都是它的子集。 |
| **LLM** | 大语言模型 | "超级读书机器人"——读遍互联网上几乎所有文字，学会了"接话"和"回答问题"。ChatGPT、Claude、文心一言都是 LLM。 |
| **Prompt** | 提示词 / 指令 | 你跟 AI 说的话。输入框里打的每一个字就是 Prompt。用大白话说就行，不需要写代码。 |
| **Token** | 词元 | AI 处理文字的最小单位。一个中文字约等于 1-2 个 Token。Token 数量决定了 AI"思考"的成本和上下文上限。 |
| **ChatGPT** | - | OpenAI 公司出品的聊天 AI，2022 年底发布后引爆了全球 AI 热潮。 |
| **Claude** | - | Anthropic 公司出品的 AI，在编程和安全方面表现突出。Claude Code 是目前排名第一的 AI 编程工具。 |
| **AI Agent** | AI 智能体 | 能"自己思考、自己动手"的 AI。不像聊天机器人你问一句它答一句，Agent 能自己用工具、执行任务、检查结果。 |
| **ReAct 循环** | 推理-行动循环 | Agent 的思考方式：想（分析任务）→ 做（调用工具）→ 看（检查结果）→ 再来（继续下一步）。 |
| **Vibe Coding** | 氛围编程 | 用大白话描述需求，让 AI 写代码，你只负责判断"对不对"。Andrej Karpathy 2025 年初提出，柯林斯词典 2025 年度词汇。 |
| **Agentic Engineering** | Agentic 工程 | Vibe Coding 的进阶版——不只是让 AI 写代码，而是建立一套标准的工作流、Skills 和验证体系。 |
| **Context Engineering** | 上下文工程 | 给 AI 提供足够多、足够准确的背景信息，比写好 Prompt 更重要。比如告诉 AI 你的项目是什么、用了什么技术、有什么规范。 |
| **MCP** | 模型上下文协议 | "AI 应用的 USB-C 接口"——由 Anthropic 发明的开放标准，让 AI 能连接各种外部工具和数据源。2026 年已有 60000+ 个公开 MCP 服务器。 |
| **Function Calling** | 函数调用 / 工具调用 | AI 调用外部工具的方式。比如 AI 想查天气，它就调用天气 API 的函数。这是 Agent "做事"的关键机制。 |
| **RAG** | 检索增强生成 | 让 AI 在回答问题前先"翻书"——从你的文档、数据库中找到相关内容，再基于这些内容回答。用于搭建私有知识库问答。 |
| **Hallucination** | 幻觉 | AI "一本正经地胡说八道"——自信地给出一个看起来合理但其实错误的信息。使用 AI 时最大的坑之一。 |
| **Cursor** | - | 目前最流行的 AI 编程编辑器（IDE），年收入 20 亿美元。深度理解你的整个项目，能自动在多文件之间修改代码。 |
| **Lovable / Bolt.new** | - | 浏览器端 AI 应用生成器。完全不需要编程基础，用自然语言描述需求即可生成完整应用。零基础入门首选。 |
| **Fine-tuning** | 微调 | 用特定领域的数据"小补课"一个现有的 AI 模型，让它更擅长某个特定任务。相当于在通才的基础上培养专才。 |
| **Open Source Model** | 开源模型 | 代码和权重公开的 AI 模型，可以免费使用、修改和部署。比如 Llama（Meta出品）、Qwen（阿里出品）、DeepSeek。 |
| **SWE-bench** | 软件工程基准测试 | 衡量 AI 解决真实软件 bug 能力的"考试"。2026 年顶级 Agent 得分 80-95%。 |
