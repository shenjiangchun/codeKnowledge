# 方案1: 多Agent协作诊断系统

## 依赖层级声明

### 依赖的前置版本/模块
| 模块 | 版本要求 | 依赖原因 |
|------|---------|---------|
| ClaudeSdkService | v1.0+ | 提供基础LLM调用能力 |
| LogAnalysisRepository | v1.0+ | 日志数据存储 |
| GlobalAnalysisCache | v1.0+ | 分析结果缓存 |
| 数据采集层 | v1.0+ | 代码/日志数据输入 |

### 可独立开发的部分
- Agent框架基础架构
- 诊断Agent核心逻辑
- 结果编排器
- 验证器

### 与其他方案的解耦点
| 方案 | 解耦方式 |
|------|---------|
| 方案2（语义理解） | 通过标准接口调用，不直接依赖内部实现 |
| 方案3（自然语言入口） | 作为上游入口，通过API调用本系统 |

## 目标与价值

### 目标定义
构建一个多Agent协作的智能诊断系统，通过多个专业化Agent的协同工作，实现从日志输入到可执行修复建议的端到端自动化诊断流程。

**核心目标**：
1. 多轮对话式根因分析
2. 多Agent协作提高诊断准确率
3. 生成可执行的修复建议

### 用户价值
| 用户角色 | 价值描述 |
|---------|---------|
| 开发工程师 | 快速定位线上问题根因，减少排查时间 |
| 运维工程师 | 获取可执行的修复建议，快速恢复服务 |
| 技术Leader | 积累诊断知识，提升团队问题解决能力 |

### 技术价值
1. **Agent架构创新**：多Agent协作模式，可扩展性强
2. **工具调用能力**：LLM可调用工具获取实时数据
3. **结果验证机制**：自动验证诊断结果，降低幻觉风险

### 核心组件

#### 1. AgentOrchestrator（协调器）

```java
public interface AgentOrchestrator {
    /**
     * 执行诊断任务
     * @param request 诊断请求
     * @return 诊断结果
     */
    DiagnosisResult diagnose(DiagnosisRequest request);

    /**
     * 多轮对话
     * @param sessionId 会话ID
     * @param message 用户消息
     * @return Agent响应
     */
    AgentResponse chat(String sessionId, String message);

    /**
     * 任务分发
     * @param task 任务
     * @param agentType Agent类型
     */
    void dispatch(Task task, AgentType agentType);

    /**
     * 结果合并
     * @param results 多个Agent结果
     * @return 合并后结果
     */
    DiagnosisResult merge(List<AgentResult> results);
}
```

#### 2. 诊断Agent

```java
public interface DiagnosisAgent {
    /**
     * 分析日志
     * @param logEntry 日志条目
     * @return 诊断结果
     */
    DiagnosisResult analyze(LogEntry logEntry);

    /**
     * 解析堆栈
     * @param stackTrace 堆栈信息
     * @return 解析结果
     */
    StackAnalysis parseStackTrace(String stackTrace);

    /**
     * 匹配历史案例
     * @param errorPattern 错误模式
     * @return 相似案例
     */
    List<Case> matchCases(String errorPattern);

    /**
     * 生成修复建议
     * @param rootCause 根因
     * @return 修复建议
     */
    FixSuggestion suggestFix(RootCause rootCause);
}
```

#### 3. 工具调用层

```java
public interface ToolRegistry {
    // 文件读取
    String readFile(String filePath);

    // 代码搜索
    List<CodeLocation> searchCode(String query);

    // 数据库查询
    QueryResult queryDb(String sql);

    // 调用链追踪
    CallChain traceChain(String entryPoint);

    // 日志查询
    List<LogEntry> queryLogs(LogQuery query);
}
```

### 数据流

```
1. 用户输入错误日志
        ↓
2. AgentOrchestrator 接收请求，创建诊断会话
        ↓
3. 诊断Agent 分析日志，提取关键信息
        ↓
4. 调用工具获取补充信息（代码、数据库、日志）
        ↓
5. 分析Agent 评估影响范围
        ↓
6. 验证Agent 校验诊断结果
        ↓
7. 结果合并，生成可执行建议
        ↓
8. 返回用户，支持多轮对话追问
```

### 技术选型

| 组件 | 选型 | 理由 |
|------|------|------|
| Agent框架 | 自研 + Spring AI | 灵活性高，复用现有ClaudeSdkService |
| LLM | Claude 4 + 本地模型 | 主模型推理强，本地模型降级 |
| 缓存 | Redis | 高性能，支持分布式 |
| 向量存储 | pgvector | 复用OpenGauss，运维成本低 |
| 消息队列 | RabbitMQ | 异步任务处理 |
