# 任务拆分

输入是 Spec（目标、验收标准、测试用例、非目标）。

## 规则

- 每个任务可独立验证：一个文件、一个方法或一个明确的落点，能说清「改什么 + 怎么验证」。
- 实现任务在前、测试任务在后；构建文件缺口（缺测试依赖/插件）单独成任务并注明要补什么。
- 每个任务给 file（相对项目根）、anchor（类#方法，可选）、verify（验证方式）。
- 任务数控制在 2-5 个：太少说明拆得不够，太多说明按 Spec 拆。
