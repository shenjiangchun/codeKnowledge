## 1. 模块概述

### 1.1 职责定义

**核心职责**：把「技能」（给编码助手用的 SKILL.md、钩子脚本、设置片段）安装到项目目录或用户目录，管理 MCP 安装包的下载与安装，并提供提示词模板的读写与渲染。

这里的「技能」有三处，互不相同：

| 名称 | 位置 | 用途 | 安装目标 |
|------|------|------|---------|
| 技能市场条目 | `SkillServiceImpl` 中以代码定义 | 面向使用 `claude` CLI 的项目 | 项目目录下的 `.claude/` |
| KG Skills 套件 | `KgSkillsKitController` 中以代码定义 | 全局的图谱检索 / 追踪 / 诊断技能 | 用户目录下的 `.claude/skills/` |
| pi skills | `resources/pi-skills/<name>/SKILL.md` | 后端 agent 流的提示词正文 | pi 配置目录下的 `skills/`，由 `PiAgentInstaller` 启动时同步 |

### 1.2 核心文件清单

| 文件 | 类型 | 职责 |
|------|------|------|
| `skill/SkillController.java`、`skill/SkillService(Impl)` | REST / 服务 | 技能定义查询、项目安装状态检测 |
| `skill/model/*`（5 个） | 模型 | `SkillDefinition`、`SkillDetail`、`SkillFile`、`SkillListResponse`、`ProjectSkillStatus` |
| `controller/SkillMarketController.java` | REST | 技能列表、安装、卸载、检查更新、升级 |
| `controller/KgSkillsKitController.java` | REST | 全局 KG 技能套件的安装 / 卸载 |
| `controller/McpController.java` | REST（含 SSE） | MCP 安装包信息、下载、安装进度、状态、配置模板 |
| `controller/PromptController.java`、`service/PromptService(Impl)`、`repository/PromptRepository` | REST / 服务 / 仓储 | 提示词模板 |

## 3. 技能

### 3.1 `/api/skills`（`skill/SkillController`）

鉴权：全部 GET，放行。

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/api/skills/list` | 技能定义列表 |
| GET | `/api/skills/status?projectDir=` | 项目已安装状态 |
| GET | `/api/skills/detail/{id}` | 技能详情 |
| GET | `/api/skills/categories` | 分类 |
| GET | `/api/skills/by-category?category=` | 按分类列出 |

`SkillServiceImpl` 的分类常量：`mcp`、`hook`、`backend-skill`、`frontend-skill`、`general-skill`。技能条目以代码定义，每条含若干 `SkillFile`（`source` 来源相对路径、`target` 安装目标、`type`）。安装目标都位于项目目录的 `.claude/` 下：

| 目标 | 来源（`source`） |
|------|----------------|
| `.claude/settings.json` | `mcp/hisi-dev-tool-mcp` |
| `.claude/hooks/pre-tool-use.js`、`.claude/hooks/skill-forced-eval.js` | `hooks/` 下的同名文件 |
| `.claude/memory/lessons.md` | `memory/lessons.md.template` |
| `.claude/skills/<name>/SKILL.md` | `skills/<name>/SKILL.md`，`name` 取 `lesson-learned`、`crud-development`、`api-development`、`database-ops`、`error-handler`、`ui-pc`、`http-client`、`code-patterns`、`git-workflow`、`bug-detective` |

`source` 的解析基准未在本次阅读中确认；`resources/codeai-skills/skills/` 下实际只有 `crud-development` 与 `lesson-learned` 两个目录。

项目安装状态的检测方式：看 `.claude/skills/*/SKILL.md` 是否存在、`.claude/hooks/` 下有哪些文件、`.claude/settings.json` 是否存在。

### 3.2 `/api/skill-market`（`controller/SkillMarketController`）

鉴权：GET 放行；POST 需要管理员。

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/api/skill-market/list` | 技能列表，含各分类计数 |
| GET | `/api/skill-market/project-status?projectDir=` | 项目安装状态 |
| GET | `/api/skill-market/detail/{id}` | 详情 |
| POST | `/api/skill-market/install` | 安装到项目 |

## 4. MCP 安装 `/api/mcp`（`controller/McpController`）

| 方法 | 路径 | 返回类型 | 说明 |
|------|------|---------|------|
| GET | `/api/mcp/info` | `Map` | MCP 包信息与工具清单 |
| GET | `/api/mcp/download` | `ResponseEntity<Resource>` | 下载安装包 |
| POST | `/api/mcp/install` | `SseEmitter`（`text/event-stream`） | 安装：检查 node，执行 `npm install` 与 `npm run build`，进度经 SSE 推送 |
| GET | `/api/mcp/status?mcpDir=` | `Map` | 状态：`node_modules` 是否存在、CLI 设置里是否配置了 MCP 服务等 |
| GET | `/api/mcp/config-template` | `Map` | MCP 配置模板 |
| GET | `/api/mcp/install-script` | `Map` | 安装脚本 |

这组接口直接返回 `Map`，不包 `ApiResponse`。配置键 `mcp.project.path`（默认空）。安装流程涉及用户目录下的 `.claude/settings.json` 与 `.claude/skills/`。

> 这条链路服务于「把 `hisi-mcp-server` 装给本机的编码助手」。后端自己的 agent 流使用 `hisi-mcp-server` 的方式不同：由 `PiAgentInstaller` 生成 `mcp.json` 并按会话拉起，见 [pi-agent底座](./pi-agent底座.md)。

## 5. 提示词模板 `/api/prompts`

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/api/prompts` | 全部模板 |
| GET | `/api/prompts/{key}` | 单个模板 |
| PUT | `/api/prompts/{key}` | 更新，请求体 `{content, variables}` |
| POST | `/api/prompts/{key}/render` | 渲染，请求体为变量名到值的 `Map` |
| POST | `/api/prompts/extract-variables` | 从文本抽取变量，请求体 `{content}` |

鉴权：GET 放行；PUT / POST 需要管理员。

| 项目 | 说明 |
|------|------|
| 变量语法 | `#{name}`（`PromptServiceImpl.VARIABLE_PATTERN`）；旧 wiki 写的 `{{var}}` 与代码不符 |
| 表 | `prompt_template`：`template_key`（PK）、`name`、`content`、`variables`、`description`、`updated_at` |
| 初始数据 | `PromptRepository.init()`（`@PostConstruct`）在模板不存在时写入 5 个内置模板 |

内置模板与变量：

| key | 名称 | 变量 |
|-----|------|------|
| `log-analysis` | 日志分析 | `errorMessage`、`errorType`、`stackTrace`、`projectPath` |
| `code-analysis` | 代码分析 | `codeSnippet`、`language`、`projectContext` |
| `trace-analysis` | 调用链分析 | `traceId`、`entryPoint`、`callChain` |
| `impact-analysis` | 影响分析 | `changedFile`、`changedMethod`、`changeType`、`projectName` |
| `free-chat` | 自由对话 | （无） |

模板正文由代码中的构建方法生成，不是从 `resources/prompts/*.txt` 读取。

## 8. 错误处理

| 场景 | 处理 |
|------|------|
| MCP 安装时未检测到 node | SSE 推送提示并终止 |
| `npm install` 或 `npm run build` 失败 | SSE 推送失败阶段，安装中止 |
| 提示词模板不存在 | `render` 记告警并返回空字符串 |

## 9. 已知问题与扩展点

| 问题 | 说明 |
|------|------|
| 两套技能入口并存 | `/api/skills` 与 `/api/skill-market` 分类体系不同（前者按载体，后者按用途） |
| 分类注释与统计不一致 | `SkillMarketController` 类注释列了 5 类（含 `other`），`categoryStats` 只初始化 4 类 |
| `/api/mcp/*` 返回类型不统一 | 直接返回 `Map`，不走 `ApiResponse` |
| 多个资源文件未见加载方 | 见第 6 节 |

| 扩展点 | 方式 |
|-------|------|
| 新增技能条目 | 在 `SkillServiceImpl` 或 `SkillMarketController` 的技能定义处增加一条并指定安装目标 |
| 新增提示词模板 | 调 `PUT /api/prompts/{key}` 覆盖，或在内置模板表里加一行 |
