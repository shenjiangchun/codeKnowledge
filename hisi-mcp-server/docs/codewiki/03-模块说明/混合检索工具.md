## 1. 模块概述

### 1.1 职责定义

**核心职责**：提供唯一的工具 `hybrid_search`，把自然语言查询 POST 到后端的语义检索 v2 接口（多路召回 + 加权 RRF 融合）；结果为 0 条时自动附上可用项目列表，提示 AI 换路径重试。

**职责边界**：

| 本模块负责 ✅ | 本模块不负责 ❌ | 由谁负责 |
|-------------|---------------|---------|
| `hybrid_search` 的 schema 与请求体组装 | 分词、多路召回、RRF 融合、精排 | 后端 |
| `limit`、`graphDepth` 的默认值 | 向量化与索引 | 后端 |
| 0 结果时回查可用项目 | 是否必须先设项目范围 | [项目范围管理](./项目范围管理.md)（本工具是严格工具） |
| 把 `language` 包装成 `filters.language` | 前后端绑定目录的范围展开、前端节点合并 | 后端 |

## 4. 内部实现

### 4.1 请求体

| 字段 | 取值 |
|------|------|
| `query` | 入参原值 |
| `projectPath` | `projectPath`，没有则取 `projectPaths[0]` |
| `projectPaths` | `projectPaths`，没有则 `[projectPath]`（两者都没有时为 `undefined`，JSON 里不出现） |
| `limit` | `limit ?? 10` |
| `graphDepth` | `graphDepth ?? 0` |
| `filters` | 仅当 `language` 有值时出现：`{ language }` |

请求体里没有 `threshold`（旧版有过，随切到 v2 接口一并删除）。

### 4.2 0 结果回退

判定条件：`results` 是数组时取其长度，否则取 `total`，再否则按 0 处理。结果为 0 时：

1. 请求已建图项目列表，成功则在原响应上追加三个字段：
   - `_hint`：固定文案，提示「可能是 projectPath 不在已建图的项目里」，让 AI 从 `availableProjects` 选一个路径重搜，或先调用 `kg_list_projects` 让用户选择。
   - `availableProjects`：项目列表接口的响应。
   - `requestedProjectPath`：本次请求体里的 `projectPath`。
2. 回查失败时静默忽略，返回原始的空结果。

代码注释说明了意图：0 结果时附上可用项目列表，让 AI 请用户选对项目后重试。

### 4.3 处理函数

实例由模块级变量 `_vecTools` 惰性创建，进程内只创建一次；入参经类型断言后直接传给 `hybridSearch()`。

## 10. 已知问题与扩展点

| 已知问题 | 影响 |
|---------|------|
| `availableProjects` 的类型标注是 `string[]`，但项目列表接口返回的是后端的通用响应信封，路径数组在它的 `data` 字段里；运行时它是一个对象 | `_hint` 让 AI「从 availableProjects 中选路径」，AI 需要自己从 `data` 里取 |
| 后端在检索过程抛异常时也返回 HTTP 200 与空结果 | 这种失败会被当成 0 结果，触发项目列表回查与 `_hint`，提示方向有误导 |
| `_hint` 文案只提到 `projectPath` | 用 `projectPaths` 调用时提示不完全对应 |
| `graphDepth` 入参在 v2 路径下不生效（见其说明文字） | 传了也没有效果 |

| 扩展点 | 扩展方式 |
|--------|---------|
| 暴露更多检索选项（例如精排开关） | 在 `inputSchema` 加字段，并在 `hybridSearch()` 里放进请求体 |
| 让 `_hint` 更准确 | 根据入参里实际用的是 `projectPath` 还是 `projectPaths` 生成文案 |
