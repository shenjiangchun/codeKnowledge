## 一、产品概述

### 1.1 产品定位

**HiSi DevTool** 是一款 **LLM原生** 的开发者工作台，旨在让AI成为懂项目的开发伙伴。

### 1.2 核心价值

| 维度 | 说明 |
|------|------|
| **LLM原生** | 以大模型为核心驱动，而非辅助工具 |
| **开发者视角** | 从开发者需求出发，而非运维视角 |
| **懂项目** | 建立代码语义图谱，理解项目上下文 |
| **开发伙伴** | 人机协作模式，而非单纯工具调用 |

### 1.3 核心能力

```
传统工具：提供数据 → 人工分析 → 得出结论
HiSi DevTool：提供问题 → AI理解 → 人机协作 → 可执行建议

差异化优势：
├── 代码级根因定位（而非日志聚合）
├── 项目语义理解（而非通用知识）
├── 多轮交互式诊断（而非一次性报告）
└── 可执行修复建议（而非问题描述）
```

## 三、新功能介绍

### 3.1 多Agent协作诊断系统

#### 功能说明

通过多个专业Agent协作分析问题根因，提供更准确的诊断结果。

#### Agent列表

| Agent | 职责 | 优先级 |
|-------|------|--------|
| **StackTraceAgent** | 堆栈异常分析，定位异常根因 | 10 |
| **AnalysisAgent** | 影响评估与风险评分分析 | 20 |
| **VerificationAgent** | 结果验证与置信度评估 | 30 |

#### 使用方式

```
用户输入问题 → AgentOrchestrator编排 → 多Agent并行分析 → 结果汇聚 → 输出诊断报告
```

#### 特性

- **流式输出**: 通过SSE实时推送诊断进度
- **置信度机制**: 每个诊断结果附带置信度评分(0-100)
- **多轮对话**: 支持上下文关联的连续诊断

---

### 3.2 代码语义理解系统

#### 功能说明

将代码理解从"文本匹配"升级为"语义理解"，构建代码知识图谱。

#### 核心组件

| 组件 | 功能 | 输入/输出 |
|------|------|----------|
| **CodeSemanticParser** | 代码语义解析 | Java源码 → MethodSemantic |
| **ExceptionPathAnalyzer** | 异常传播路径分析 | 异常类型 → 传播路径 |
| **IntentAnnotator** | 方法意图标注 | 方法代码 → 意图描述 |
| **CodeKnowledgeGraph** | 代码知识图谱存储 | 语义数据 → 图结构 |

#### 支持的语义信息

- **方法签名**: 类名、方法名、参数、返回类型
- **代码结构**: 圈复杂度、调用关系、异常声明
- **语义标注**: 方法意图、关键词、分类

#### 圈复杂度计算

支持以下控制流结构的复杂度计算：
- if/else 条件语句
- for/while 循环
- switch/case 分支
- try-catch 异常处理
- 逻辑运算符 (&&, ||)
- 三元运算符 (?:)

---

### 3.3 自然语言诊断入口

#### 功能说明

让开发者用自然语言与系统交互，无需学习复杂命令。

#### 支持的意图类型

| 意图类型 | 描述 | 示例 |
|---------|------|------|
| **DIAGNOSE_ERROR** | 诊断错误 | "帮我分析这个NullPointerException" |
| **ANALYZE_LOG** | 分析日志 | "分析这段日志找出问题原因" |
| **SEARCH_CODE** | 搜索代码 | "找到UserService中的login方法" |
| **EXPLAIN_CODE** | 解释代码 | "解释这个方法的作用" |
| **SUGGEST_FIX** | 建议修复 | "这个异常怎么修复" |
| **TRACE_CHAIN** | 追踪调用链 | "追踪这个方法的调用来源" |

#### 交互示例

```
用户: 帮我分析这个NPE错误，重点关注认证逻辑
系统: 收到，正在分析NullPointerException...
      检测到authToken未校验，置信度92%
      建议修复: 在login方法入口添加token非空检查
```

#### 特性

- **零学习曲线**: 新用户上手时间 < 5分钟
- **混合识别**: 规则优先 + LLM补充的混合模式
- **多轮对话**: 支持上下文保持和追问

### 3.4 变更影响预测系统

#### 功能说明

预测代码变更对系统的影响范围，生成风险评估和测试建议。

#### 核心能力

| 能力 | 描述 |
|------|------|
| **调用链追踪** | 追踪方法调用链至入口点 |
| **影响范围分析** | 识别受影响的类、方法、URI、MQ端点 |
| **风险评估** | 自动评估变更风险等级 |
| **测试建议** | 生成针对性的测试用例建议 |

#### 风险评估维度

| 维度 | 权重 | 说明 |
|------|------|------|
| 影响范围 | 30% | 受影响组件数量 |
| 业务关键性 | 25% | 是否涉及核心业务 |
| 代码复杂度 | 20% | 方法的圈复杂度 |
| 测试覆盖率 | 25% | 现有测试覆盖情况 |

#### 风险等级

| 等级 | 分数范围 | 建议操作 |
|------|---------|---------|
| **LOW** | 0-30 | 可直接发布 |
| **MEDIUM** | 31-60 | 需要代码审查 |
| **HIGH** | 61-80 | 需要全面测试 |
| **CRITICAL** | 81-100 | 需要架构评审 |

---

### 3.5 历史案例匹配

#### 功能说明

从历史故障案例库中匹配相似问题，提供参考解决方案。

#### 核心组件

| 组件 | 功能 |
|------|------|
| **CaseMatchingService** | 历史案例匹配服务 |
| **FixSuggestionService** | 修复建议生成服务 |

#### 匹配流程

```
当前问题 → 特征提取 → 案例库检索 → 相似度排序 → 返回匹配案例
```

## 七、常见问题

### Q1: 如何提高诊断准确率？

**A**: 提供更完整的问题上下文：
- 包含完整的堆栈信息
- 提供相关的日志内容
- 说明业务场景和预期行为

### Q2: 影响预测支持哪些变更类型？

**A**: 目前支持：
- `ADD`: 新增方法/类
- `MODIFY`: 修改现有代码
- `DELETE`: 删除方法/类
- `REFACTOR`: 重构代码

### Q3: 如何添加自定义Agent？

**A**: 实现 `DiagnosticAgent` 接口：

```java
@Component
public class CustomAgent implements DiagnosticAgent {

    @Override
    public String getName() {
        return "CUSTOM";
    }

    @Override
    public int getPriority() {
        return 50;
    }

    @Override
    public AgentResult execute(AgentContext context) {
        // 实现诊断逻辑
        return AgentResult.builder()
            .success(true)
            .summary("诊断结果")
            .build();
    }
}
```

### Q4: 支持哪些编程语言的语义分析？

**A**: 目前支持：
- Java (完整支持)
- 其他语言支持计划中

### Q5: 如何配置知识图谱存储？

**A**: 默认使用内存存储，如需持久化可配置图数据库：

```yaml
knowledge-graph:
  storage: nebula  # 或 memory
  nebula:
    hosts: localhost:9669
    space: hisi_devtool
```

### Q6: 流式输出的超时时间是多少？

**A**: 默认超时时间为60秒，可通过配置调整：

```yaml
spring:
  mvc:
    async:
      request-timeout: 60000
```
