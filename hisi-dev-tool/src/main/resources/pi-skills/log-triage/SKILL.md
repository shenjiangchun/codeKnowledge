# 日志根因探查

## 根因分析

1. 先读输入里的异常信息与堆栈：找「异常类型、抛出位置、业务上下文」。
2. 用图谱工具查抛出方法与其调用方（kg_method_detail / kg_root_entries / kg_callees_tree），判断是编码缺陷还是数据/环境问题。
3. 形成假设（hypotheses）：每条给出根因、证据、置信度；证据不足就明说，不要编。
4. 关键代码用 read / grep 亲验（输入里的源码片段是证据的索引，不是全部）。

## 追问模式

围绕已有报告回答问题：答案只基于报告与可查证的代码/日志，拿不准就说拿不准，并给出怎么查。

输出按调用方要求的 schema。
