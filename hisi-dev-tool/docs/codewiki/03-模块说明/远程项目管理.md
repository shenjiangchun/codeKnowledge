## 1. 职责边界

| 做什么 | 不做什么 | 由谁负责 |
|---|---|---|
| 远程项目登记、克隆、拉取、删除 | 构建知识图谱 | `knowledgegraph` |
| 凭据加密存储与解密使用 | 用户认证 | JWT 过滤器 |
| 按 appId / 名称模式给项目分组 | 分组级联删除时的关联清理 | 无（见问题 6） |
| 按 cron 触发 KG 增量或全量 | 任务排队与执行 | `knowledgegraph/service/KgGenerationQueue` |
| 术语表 CRUD | 术语注入提示词 | `knowledgegraph/service/LLMDescriptionService` |
| Java 桥接端点扫描并写入全局缓存 | 调用关系解析 | `knowledgegraph/service/KnowledgeGraphBuilder` |
| 定时拉取日志并提交分析 | 日志诊断 | `service/LogAnalysisExecutor` |

### 2.1 克隆流程

```mermaid
sequenceDiagram
    participant FE as "前端"
    participant CT as "RemoteProjectController"
    participant SV as "RemoteProjectService"
    participant RE as "RemoteProjectRepository"
    participant GT as "JGit"
    FE->>CT: POST /api/remote-projects
    CT->>SV: create
    SV->>SV: 加密口令或令牌
    SV->>RE: insert 状态 PENDING
    FE->>CT: POST /{id}/clone
    CT-)SV: runAsync cloneProject
    CT-->>FE: Clone started
    SV->>RE: updateCloneStatus CLONING
    SV->>GT: cloneRepository setBranch
    GT-->>SV: 成功或异常
    SV->>RE: 写 fullPath 与 CLONED 或 FAILED
```

### 2.2 克隆状态机

```mermaid
stateDiagram-v2
    [*] --> PENDING
    PENDING --> CLONING: 触发 clone
    CLONING --> CLONED: 克隆成功
    CLONING --> FAILED: 克隆异常
    FAILED --> CLONING: 再次触发 clone
    CLONED --> [*]: 删除项目
```

## 5. 错误处理

| 场景 | 处理 | 位置 |
|---|---|---|
| id 不存在 | `RuntimeException` → 500 | `project/remote/service/RemoteProjectService.java:47-50` |
| 克隆失败 | 只记 `FAILED` + 根因消息（截断 500 字符），不抛出 | 同上 `:252-256`、`:349-360` |
| 拉取失败 | 抛 `RuntimeException`，但已在异步线程，仅记日志 | 同上 `:289-291`、`RemoteProjectController.java:87-91` |
| 删目录失败 | 吞掉异常继续删记录 | 同上 `:327-347` |
| 定时任务失败 | 仅记日志，`lastRunAt` 不更新 | `scheduler/service/KgSchedulerService.java:98-100` |
| 鉴权类型非法 | `IllegalArgumentException` | `RemoteProjectService.java:166-168` |

## 6. 已知问题与扩展点

| # | 问题 | 证据 | 扩展点 |
|---|---|---|---|
| 1 | 未配置 `hisi.encrypt.key` 时回退到源码内置默认密钥，口令/令牌等同明文存储；密钥由原始字节补零/截断得到，未经 KDF | `project/remote/service/GitCredentialService.java:23-31` | 强制配置或改用系统密钥库 |
| 2 | SSH 会话工厂是 JVM 全局单例，克隆/拉取并发时互相覆盖；`StrictHostKeyChecking=no` | 同上 `:171-195`、`:258-260`、`:293-295` | 按克隆传入 `SshSessionFactory` |
| 3 | 克隆/拉取跑在 `CompletableFuture.runAsync` 公共线程池，无并发保护、无超时，重复点击可并发克隆 | `project/remote/controller/RemoteProjectController.java:77`、`:87` | 走任务队列并限流 |
| 4 | 目标目录非空即整目录删除，`localPath` 仅由名称清洗得到，存在误删风险 | `RemoteProjectService.java:212-229`、`:318-325` | 克隆前校验目录归属 |
| 5 | 删除与拉取按 `localPath` 重算目录，不用克隆时固化的 `fullPath`；改过 `app.project_dir` 后会删错或拉错目录 | 同上 `:200-203`、`:270`、`:304-312` | 统一使用 `fullPath` |

| 9 | 建表后的补列逻辑分散两处：`SQLiteSchemaInitializer.addColumnIfAbsent` 与 Repository 内 `@PostConstruct` 探测式 `ALTER` | `RemoteProjectRepository.java:28-51` | 集中迁移 |
