### 2.2 布局结构

`AppLayout` 使用 `el-container`：左侧 `AppSidebar`，右侧纵向排列 `AppHeader`（高 48px）与 `el-main`。内容区的 `router-view` 外包了一层 `keep-alive`，组件以 `route.fullPath` 为 key——同一路由的不同参数会被视为不同实例分别缓存。

`AppLayout` 在挂载时调用 `authStore.init()`，这是应用启动后恢复登录身份的唯一起点。

## 4. 全局守卫

`router.beforeEach` 依次执行四步：

| 步骤 | 条件 | 动作 |
|------|------|------|
| 1. 标题 | `to.meta.title` 存在 | `document.title = "{title} - HiSi Dev Tool"` |
| 2. 管理员校验 | `to.meta.requiresAdmin` | 未初始化则 `await authStore.init()`；非管理员提示后 `next('/')` |
| 3. 加载项目目录 | `appStore.projectDir` 为空且 `configLoading` 为假 | `await appStore.loadProjectDir()`；失败只打 `console.error`，不阻断 |
| 4. 菜单可用性 | 见下表 | 不可用则提示"请先在项目管理页面选择项目"并 `next('/project')` |

第 4 步的检查项：

| 路径前缀 | 检查的 `availableMenus` 键 | 当前是否可能拦截 |
|---------|--------------------------|----------------|
| `/knowledge-graph` | `knowledge-graph` | 是——未选中项目时为 `false` |
| `/architecture` | `architecture-diagnosis` | 是（同上） |
| `/ram` | `ram` | 否——代码中恒为 `true` |

### 5.2 可用性规则

- 每一项的 `disabled` 取 `!appStore.availableMenus[menuKey]`。
- 禁用项加 `disabled` 样式（`pointer-events: none`）并移出 Tab 顺序。
- 带子菜单的项在禁用时不再渲染可展开的分组，而是落到普通菜单项分支，显示为一条禁用项。

### 5.3 子菜单状态

`openedSubmenus` 是一个响应式 `Set`，初始化时按当前路径展开匹配的分组，路由变化时由 `watch(route.path)` 同步；点击分组标题切换展开。
