### 3.2 `handleToolCall()`

```ts
export async function handleToolCall(
  toolName: string,
  args: Record<string, unknown>
): Promise<unknown>
```

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `toolName` | `string` | 是 | 工具名 |
| `args` | `Record<string, unknown>` | 是 | 工具入参；本函数先用归一化后的浅拷贝替换它，不修改调用方传入的对象 |

**返回值**：对应处理函数的结果（通常是后端响应 JSON）。

**调用约束**：

- 本函数不校验入参是否符合 `inputSchema`，入参原样（归一化后）转给处理函数。
- 工具名不在任何名单中时抛 `Error("Unknown tool: <toolName>")`；正常情况下不会走到这里，因为入口已经先按 `allDefsWithScope` 过滤过未知工具名。

## 4. 内部实现

### 4.1 聚合顺序

```ts
export const allToolDefinitions = [
  ...knowledgeGraphToolDefinitions,
  ...vectorToolDefinitions,
  ...logToolDefinitions,
  ...apmToolDefinitions,
  ...actToolDefinitions,
];
```

入口再追加 `kg_select_scope`，得到 `tools/list` 返回的 40 个工具，`kg_select_scope` 排在最后。

### 4.2 路径归一化的调用点

`handleToolCall()` 第一行调用 `normalizePathArgs(args)`。归一化只处理「路径型键名」：

| 值类型 | 会被归一化的键名 |
|--------|----------------|
| 字符串 | `projectPath`、`filePath`、`path`，以及任何以 `Path` 结尾的键 |
| 字符串数组 | `projectPaths`、`filePaths`、`paths`，以及任何以 `Paths` 结尾的键 |

因此有两类入参不受影响：

- 动作工具的 `project_path`（下划线命名，不匹配 `Path` 后缀）不会被归一化。
- `apm_execute_request` 的 `path` 会被归一化（命中显式键名 `path`）。

规则细节与测试见 [路径归一化](./路径归一化.md)。

## 10. 已知问题与扩展点

| 已知问题 | 影响 |
|---------|------|
| 文件头注释的工具数（22 / 33）与实际（23 / 39）不符，且未列出动作工具 | 只影响阅读，不影响行为 |

| 扩展点 | 扩展方式 |
|--------|---------|
| 新增一类工具（例如 `db_*`） | 新建 `tools/dbTools.ts`，导出定义数组、名单常量和处理函数；在本文件 import、加入 `allToolDefinitions`、加一个名单分支，并在需要时加入再导出 |
| 调整归一化规则 | 修改 [路径归一化](./路径归一化.md)，本文件不用改 |
| 让新工具受项目范围约束 | 在 `scopeManager.ts` 的 `TOOL_SCOPE_REGISTRY` 登记，本文件不用改 |
