## 二、核心创新方向

### 2.1 多Agent协作诊断系统（★★★★★）

**架构设计**：

```
┌─────────────────────────────────────────────────────────────────┐
│                    WebSocket 实时通信层                          │
│              (双向流式传输 + 用户干预接口)                        │
└─────────────────────────────────────────────────────────────────┘
                              │
                              ▼
┌─────────────────────────────────────────────────────────────────┐
│                     Orchestrator Agent                          │
│   • 任务分解: "分析NPE" → [堆栈分析, 代码检索, 变更追踪]         │
│   • 进度推送: 实时输出分析过程                                    │
│   • 用户交互: 响应用户干预指令                                    │
│   • 结果整合: 综合各Agent输出，生成最终报告                       │
└─────────────────────────────────────────────────────────────────┘
         │                │                │                │
         ▼                ▼                ▼                ▼
┌───────────────┐ ┌───────────────┐ ┌───────────────┐ ┌───────────────┐
│ StackTrace    │ │ CodeContext   │ │ GitHistory    │ │ DocRetrieval  │
│ Agent         │ │ Agent         │ │ Agent         │ │ Agent(可选)   │
│               │ │               │ │               │ │               │
│ 能力:         │ │ 能力:         │ │ 能力:         │ │ 能力:         │
│ • 堆栈解析    │ │ • 代码检索    │ │ • Git历史     │ │ • 文档检索    │
│ • 异常定位    │ │ • 语义理解    │ │ • 变更关联    │ │ • API文档     │
│ • 业务过滤    │ │ • 调用链分析  │ │ • 责任人识别  │ │               │
└───────────────┘ └───────────────┘ └───────────────┘ └───────────────┘
                              │
                              ▼
┌─────────────────────────────────────────────────────────────────┐
│                     Consensus Agent                             │
│   • 交叉验证: 多Agent结论一致性检查                               │
│   • 置信度计算: 综合各Agent置信度，加权平均                       │
│   • 证据链生成: 展示"为什么得出这个结论"                          │
│   • 决策输出: 最终根因 + 修复建议 + 置信度                        │
└─────────────────────────────────────────────────────────────────┘
```

**解决痛点**: 日志分析效率

---

### 2.2 LLM原生代码语义理解（★★★★★）

**核心突破**: 超越AST解析，让LLM理解代码意图

| 传统方式 | LLM原生方式 |
|----------|-------------|
| 语法树解析 | 语义理解 |
| 方法名匹配 | 业务意图匹配 |
| 关键词搜索 | 概念关联搜索 |

**典型场景**:
```
用户问: 这个订单为什么会失败？
LLM自动:
1. 定位OrderService相关代码
2. 追溯订单处理流程
3. 关联日志中的错误信息
4. 输出: 订单失败原因分析报告
```

**解决痛点**: 代码理解

---

### 2.3 自然语言驱动诊断入口（★★★★★）

**核心突破**: 用户不需要学习工具，用自然语言描述问题

**交互模式**:
```
用户: 最近支付功能经常超时，帮我分析一下
系统:
1. 识别"支付功能"相关代码
2. 检索近期超时日志
3. 分析调用链瓶颈
4. 输出诊断报告和优化建议
```

**解决痛点**: 全部痛点

---

### 2.4 智能变更影响预测（★★★★☆）

**核心突破**: 用LLM预测代码变更的潜在影响

**流程**:
```
代码变更 → LLM语义分析 → 影响范围预测 → 风险评估 → 测试建议
```

**输出**:
- 直接调用方 + 业务影响预测
- 测试用例建议
- 监控配置建议

**解决痛点**: 变更影响评估

## 五、验证方案

### 5.1 对比实验

| 实验组 | Agent配置 | 验证目标 |
|--------|----------|---------|
| A | 单Agent（当前实现） | 基准线 |
| B | 双Agent（StackTrace + CodeContext） | Agent数量影响 |
| C | 三Agent（+ GitHistory） | 完整性提升 |
| D | 三Agent + Consensus | 验证框架有效性 |

### 5.2 评估指标

| 指标 | 目标值 | 测量方式 |
|------|-------|---------|
| 根因定位准确率 | ≥80% | 100个历史案例对比 |
| 分析效率 | ≥10倍提升 | 人工 vs 自动耗时 |
| 用户干预有效性 | 提升≥10% | 干预前后准确率对比 |
| 置信度可信度 | 相关性≥0.85 | 高置信度案例实际准确率 |

## 七、风险评估

| 风险项 | 影响 | 缓解措施 |
|--------|------|---------|
| Claude CLI生产不可用 | 高 | 优先评估，备用纯远程LLM |
| 缓存内存溢出 | 中 | Caffeine限制1000条 + TTL 24h |
| WebSocket前端未配合 | 中 | 提供 Mock 接口，提前沟通 |
| 响应体内存泄漏 | 高 | try-with-resources |
| 超时僵尸连接 | 高 | call.cancel() |
